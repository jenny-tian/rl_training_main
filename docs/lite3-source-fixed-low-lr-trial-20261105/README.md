# Source 固定低学习率两轮对照试验

用户在收到详细方案后明确同意执行本阶段：从原 `model_1998.pt` 出发，将学习率固定为 0.00001，最多进行两次 PPO 更新，并分别复评第 1、2 轮模型。阶段结束后汇报结果，后续阶段另行征求同意。本提交先固定代码和准备记录，实际结果将在执行后补充。

保留 `lite3_source_lowspeed_v1` 奖励、checkpoint 的 12 维探索标准差、全新 critic 与 optimizer、run1 种子、120 个 L1 环境、24 步 rollout 和其余 PPO 参数。actor 和 critic 共用 optimizer，因此两者学习率同时降低。此比较先检验整体更新幅度的影响，不能单独识别 actor 或 critic 的因果作用。

训练最多 5760 条交互，累计计费从 265344 增至 271104。原有失败记录和旧预算上限保留；本次预留后不自动退款或重试。两模型各进行 400 步确定性复评，共最多 96000 条诊断交互。沿用原场景、初态和预先固定的门槛：速度至少 0.251111 m/s，速度均方根误差至多 0.120849 m/s，每步奖励至少 0.077734，动作裁剪比例至多 1%，400 步回合结束数为 0。

执行入口为 [source_fixed_lr_trial.py](../../scripts/tools/source_fixed_lr_trial.py)。每个真实训练小批次在 optimizer 步骤前后记录相对于 rollout 策略的 KL，并记录实际学习率。另在每次完整 PPO 更新后，使用原模型第 1、100、200、400 步的 480 个保存观测，记录相对于原策略的动作变化和 KL。两类 KL 的输入分布不同，分别解释。

监控不执行 KL 早停、不修改梯度或学习率、不额外采样随机动作。12 项针对性 CPU 检查通过，耗时 1.64 秒。启用监控后的损失、actor、critic、optimizer 和随机数状态与未启用监控的实际 PPO 更新逐项相等；检查也覆盖日志计数、已知动作偏移、学习率漂移拒绝、异常后 hook 恢复以及预算历史保护。CPU 合成检查不构成 Isaac 仿真或真实训练交互。

运行总期限 300 秒，阶段默认期限 120 秒，环境与应用关闭各限 15 秒。每轮保存 actor，第 2 轮另存完整模型状态。结果、逐地形比较、原始记录、哈希和下一阶段方案会一并归档。
