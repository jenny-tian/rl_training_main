## 性能修复与补充 G3 的批准前准备记录

在已保存的真实接触帧上测得旧编码约 0.340 秒/物理步，其中整矩阵 SHA256
约 0.182 秒。8004 个物理步仅该编码就约需 45 分钟，路径/JSON 优化不足以
达到 30 分钟预算，因此继续等待旧实现不能解决问题。

新路径在设备端逐项检查完整 dense force/count、提取 count 非零或 force
位非零的联合集、比较 dense sum/net；CPU 只接收有效 pair/point 和独立从
原矩阵提取的非零块。查询间先完成设备拷贝，避免 PhysX 借用缓冲被后续读取
覆盖。正常路径不把百万容量的未用接触槽搬到 CPU；失败时仍完整保存原生缓冲。

完整性格式明确改为 `sha256_blocks_4096_v1`：每 4096 字节一个 SHA256，固定
零块复用已知 SHA，再将形状、dtype 和完整顺序块哈希列表绑定到根 SHA。每个
原生矩阵元素仍属于一个块；隐式零不丢弃覆盖。CPU 独立按 sparse pair/point
恢复完整的零填充逻辑数组，重算块 SHA；需要时可物化为 dense 数组并逐项比较。
测试覆盖 force-only、次正规位、signed zero、padding、跨环境接触、容量饱和、
缺失点/配对、改写根哈希和 reset/action 证据。真实帧恢复值完全一致。

同一真实帧 CPU 基准：整数组哈希 0.182 秒，分块哈希 0.072 秒，独立逻辑
重建约 0.066 秒。CPU 上执行完整新路径约 0.424 秒，不能将其当成 GPU 提速
结果；新设备端路径的实际吞吐尚未测量。最新定向验证 89 passed，0 failed、
0 skipped，32.80 秒；另有包含旧 sparse 路径的 114 passed 结果，全部是 CPU。
没有再次运行 1091 项整组，也没有把合成 fixture 标为真实运行通过。

现有真实 G2 不再重跑。250 项旧输入逐字节未变，剩余六项是 G3/授权代码或

topology、公用入口及默认 decoder 的完整逻辑；reset、物理、资产和训练环境

独立地形成功率或正式选模资格。
