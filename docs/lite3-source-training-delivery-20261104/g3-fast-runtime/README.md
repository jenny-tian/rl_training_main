## 这次修复证明了什么

保存的日志已经越过原第 507 步故障位置，没有重现 nonfinite scanner evidence。
原故障涉及的环境 34 在本轮第 460 步因 source_terrain_tile_bounds 正常终止并
reset，进度为 -0.488204479 米，见 `raw/env34_reset_observation.json`。这支持
提前扫描边界保护在该实际场景生效；本轮仍缺完整采集和独立复核，不能扩展为
全时段或所有场景安全结论。

前 64 步实测采集约 51.61 秒，旧实现为 159.21 秒，前缀约快 3.1 倍；本轮
到 1856 步已用 1736.05 秒采集时间，启动和收尾也计入 1800 秒上限。前缀速度
检查没有覆盖后续普通 reset 增多时的开销，实际整轮仍超时。当前数据没有将全部
耗时分解到 reset、物理和证据生成，不能把速度下降全部归因于某一模块。

此外，本轮冻结 actor 加标准差为 1 的随机动作噪声，与历史确定性 Flat 测试的
动作条件不同。历史确定性测试 1514 步达到 9.295 米，不保证本轮也能达到 9 米。
当前最远 3.9067 米、无完成回合，即使仅延长时间补齐剩余 117 步，也不能据此
预测能够满足 Flat 要求。没有自动延长、降噪、降低标准或重试。

## 原始报告的限制与归档

超时中断前，result.json 只写过 initial-ready 快照，仍为 status=running、
simulation_control_steps=0；最终累计报告和正常 cleanup 未写回。该原件完整保留，
没有回填为完成。控制日志统计和监督执行记录单独保存，避免把初始快照当最终结果。
CPU 验收实际拒绝理由是 G3 execution failed，不应写成它已独立验证后发现 Flat
失败。Flat 证据缺失来自另行统计的已保存控制记录。

结束后另行执行 `gzip -t`，压缩容器完整性检查通过，见
`raw/gzip_container_check.json`。这说明保存的压缩文件可完整解压，不代表其中
接触、扫描和动作内容已完成独立验证。

`raw/runtime_artifacts.json` 列出本轮全部原件的路径、大小及 SHA256。事件日志约
2.44 GB，控制日志约 704 MB，保留在本机持久目录，仓库只提交索引；其余小型原件
随仓库归档。原始 checkpoint SHA256 和训练台账 SHA256 均与运行前相同。

运行 `python review.py` 核对归档哈希、实际超时/拒绝、完整记录统计、台账和原模型
哈希，以及大文件是否仍与索引一致。该归档检查不授予运行资格，不替代逐帧物理
证据独立复核。本阶段累计三个真实 GPU 作业：合并 G2、64 步 G3、1884 步补充 G3；
合计 234240 条只读样本，无新增 PPO 训练。
