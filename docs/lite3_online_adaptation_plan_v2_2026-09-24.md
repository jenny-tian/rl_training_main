## 1. 现状结论

截至 9/24，没有任何一组在线学习在留出地形上优于冻结 base，两组高度扫描变体比 base 更差。唯一的正信号出现在训练地形本身：101 号地形上 base 停在 0.65 m，proprio 学后冻结策略能走到 2.9–4.2 m（仍未完成）。LoRA-PPO 的 critic 在整个训练过程中没有拟合回报，这是当前最可能的技术瓶颈。

因此计划从"比较输入和方法"改为：先让学习信号成立，再在 base 失败的地形上检验在线适应。

### 2.2 学习过程诊断（各 20 回合、181 条更新记录）

| 指标 | proprio | heightscan |
|---|---|---|
| 训练回合完成 | 3/20（第 8 回合首次） | 11/20（第 1 回合即完成） |
| 同一时期在 101 上的冻结复测 | 0/4 | 0/4（第 5、20 回合只走到 0.73、0.65 m） |
| 冻结评测中学到的残差 max\|Δa\| | 0.005–0.0075 | 0.018–0.033 |
| 训练探索噪声 std | 0.03 → 0.01（按回合几何衰减） | 同左 |
| critic explained variance 中位数 | −0.18 | −0.19 |
| explained variance > 0 的更新占比 | 29% | 33% |
| approx KL 中位数（target 0.01） | 4.6e-4 | 2.7e-3 |
| 平地锚点 MSE 最大值（上限 5e-4） | 7.3e-6 | 3.7e-5 |

解读：

1. **训练回合的成败主要由探索噪声决定。** heightscan 组在第 1 回合（策略几乎还是 base）就完成了；同一批 checkpoint 在 101 上做冻结复测，却只走到 base 的停滞点附近。训练期完成率不能当作学习效果。
2. **proprio 的冻结策略几乎就是 base。** 学到的均值偏移最大只有 0.0075，还不到探索噪声的标准差，所以它在留出集上与 base 持平是意料之中的。
3. **critic 从未拟合回报。** critic 是随机初始化的 128×128 MLP，没有预热，每次更新只用 256 步数据；explained variance 在整个训练中位于 0 以下，优势估计接近噪声，更新方向接近随机。锚点约束离上限还差一到两个数量级，不是瓶颈。
4. **heightscan 确实改变了策略，但在留出种子上全面变差（负迁移）。**

### 2.5 v2.1 新核实的机制事实（2026-09-25）

1. **探索噪声大部分被安全限速器截断。** 残差变化率上限为 0.03。独立噪声相邻两步之差的标准差是 σ√2：σ=0.03 时约 0.042，超过上限；σ=0.01 时约 0.014。在 09-22/23 的三组消融中，训练期 `safety_projected_fraction` 随 σ 从 0.03 衰减到 0.01 单调下降，从 99.8% 降到 33.5%；被截掉部分的 RMS 从 0.017 降到 0.0012。σ=0.01 时的理论值（33.9%）与 09-18 审计一致。实际执行的探索是一条被截断的随机游走，而不是 PPO 假设的白噪声。requested-action PPO 仍然无偏（投影被视为环境的一部分），但探索形态已经改变；自模仿也不能靠"排除被投影的步"来筛选样本，因为那样几乎会丢掉全部数据。
2. **101 号地形的停滞点很脆弱。** proprio 组 20 个训练回合中，有 15 个越过了 base 的 0.65 m 停滞点，失败的 5 个停在 0.52–0.75 m。这说明"101 上 base 失败"很可能对微小扰动敏感，印证了 D7 用扰动起点来定义失败池的必要性。
3. **价值目标的尺度。** γ=0.99，GAE λ=0.95，完成奖励 +305，每次更新 256 步。按 0.99^200≈0.13 估算，完成奖励只影响最后约 200–300 步的价值，而 256 步的 batch 中只偶尔包含终点。这与 critic EV<0 的现象吻合。
4. **base checkpoint 带有平地 critic**（48→512→256→128→1）。它可作为在线 critic 的初始化候选，但奖励定义不同，只能复用特征层，或另加 ΔV 头。
5. **残差 SAC 的 critic 配置与近期文献不同。** 当前是双 Q、n_step=1，没有 LayerNorm 和 ensemble；critic 预热用的是平地 replay，而不是目标地形上的 base rollout。WSRL（2412.07762）报告预热数据必须来自目标任务上的预训练策略。
6. **没有逐步轨迹记录。** 每个 episode 目录只有 config、summary、updates.jsonl、latest.pt 和日志。因此，任何需要 (o_t, a_req, a_exec, r_t, x_t) 的离线预检都要先补上记录，再重跑。
7. **仓库没有仿真状态快照/恢复工具。** 只有重置事件中的 `write_joint_state_to_sim`。

## 3. 修订决定

**D1 研究问题回到学期计划的原定义：在遇到的地形上在线适应。** 主终点改为：在 base 失败的地形实例上，按固定交互预算在线学习后，冻结策略能否在该地形上稳定完成。迁移到其他实例、返回平地后的保持，作为次要终点和"不得变差"的约束。理由：现有唯一的正信号出现在训练地形上；"在 101 上训练、在另外 4 个种子上冻结验证"回答的是另一个问题（适配器的泛化），而且 4 个种子分辨不出任何差异。

**D2 撤回 09-24 审查第 4 节第 1 条（主路线定为 LoRA-PPO），暂不定主路线。** 该决定部分依据的是误读的数据。LoRA-PPO 与 residual SAC 进入同一个路线决定实验（G3），按事先登记的规则选择。

**D3（v2.1 重写）冻结高度扫描观测和高度扫描 teacher，但 steering 与 FlowDAgger 思路改为不依赖 teacher 的形式，重新进入候选。** 冻结高度扫描观测与 teacher 的依据是负迁移（2.1）和 teacher 资格检查失败（2.4），代码与测试保留。

v2 把 latent steering 一并冻结，理由不充分。失败的是"高度扫描 teacher 提供目标"这一环，而不是 steering 或 DAgger 机制本身。v2.1 用三种不需要 teacher 的纠正来源替代它：
- 成功回合中的执行动作（M1 自监督 FlowDAgger）；
- 低维行为 latent 上的无 critic 搜索（M2）；
- 仿真快照分支得到的自动纠正（M3）。

`teacher_steering.py` 中的反演和监督工具可以复用，目标改为上述三种来源。

需要注意，base 是单峰 Gaussian MLP，对它做噪声 steering 在数学上等价于按 σ 缩放的残差。只有先构造出低维行为 latent（M2），USR 式的"steering＋门控残差"（M4）才有意义。因此 M4 排在 M2 通过之后。方法定义见跨领域调研第 3 节。

**D8（v2.1 新增）探索与记录先行。**
- **逐步轨迹记录。** 所有在线 session 都记录逐步的 (o_t, a_req, a_exec, 投影标志, r_t, x_t, y_t, 已用时间)，用 float16 压缩存储。预计每回合约 1–2 MB。
- **结构化探索噪声。** 作为 G1 的一个可叠加改动，用时间相关噪声（如低通滤波或 gSDE）替代每步独立的白噪声，并使相邻两步差的标准差明显低于 0.03 的限速上限，使请求动作和执行动作尽量一致（依据 2.5 第 1 条、PoWER、gSDE）。改用新噪声后，PPO 的 log-prob 必须按新的采样分布重新推导，并用单元测试覆盖。

**D9（v2.1 新增）G1 分两条轨道并行，G3 的比较臂由各自的门槛决定。**
- 轨道 A：修复梯度方法（M0 LoRA-PPO 价值修复；残差 SAC 按 2.5 第 5 条修配置）。
- 轨道 B：无 critic 方法的廉价证伪（M2 headroom 网格、M3 快照检查、M1 预检）。

两条轨道共用 101、107 两个调试地形，占用各自的 GPU。

**D4 学习信号先行。** 任何方法比较之前，LoRA-PPO 必须先通过 G1 的学习信号门槛。

**D5 种子重新划分（协议 v2）。**

- 101–113 降为调试种子，不进入统计。
- 1009–1123 退役，不再作为封存集，可以并入开发池。
- 新建开发池：rough_4cm 和第二类地形各 40 个新实例，全部先跑冻结 base，按结果分为 base 失败池 F 和 base 成功池 S。
- 新封存种子在 12 月冻结协议时才生成，生成规则现在就写死：由 `final_protocol.json` 的 sha256 派生，剔除任何已用过的种子。在此之前没有人知道具体种子。
- 封存守卫改为：没有已提交的冻结协议文件时，拒绝一切封存运行；有冻结协议时，允许按协议登记的在线学习 session。现在的 `sealed terrain is evaluation-only` 检查与 D1 冲突，需要一并修改。

**D6 主实验收窄为两类地形。** rough_4cm（已有）和台阶（协议中已登记 `step_4cm`、`step_6cm`，按 base 难度选一档）。低摩擦作为第三类，有余力再做；连续曲面和水平弯道移到扩展，原 T06 随之推迟。10 月不再新写地形生成器。

**D7 评测加入初始状态扰动。** 当前重置完全确定（`deterministic_root_reset_params`），同一地形上的冻结评测只是一条确定轨迹，有"背下一条路线"的风险。新增带种子的小扰动（候选：x ±0.2 m、y ±0.1 m、yaw ±0.1 rad，先在平地上确认不影响 base）。"稳定完成"定义为 5 个扰动起点中至少完成 4 个。

## 4. 终点与统计

| 类别 | 定义 | 比较方式 |
|---|---|---|
| P1 主终点 | 学后冻结策略在本地形上稳定完成（D7） | base 在 F 池中按定义失败；报告完成比例和 Clopper–Pearson 区间 |
| P2 主终点 | 最后 5 个训练回合的完成率 | 与噪声对照 C（同一噪声日程、不更新）按地形配对，Wilcoxon 符号秩检验 |
| S1 次要 | 迁移：在 10 个 S 池实例上完成数相对 base 的变化 | 负迁移上限：丢失 ≤ 1/10 |
| S2 次要 | 平地保持：现有 flat retention 协议的稳态速度误差 | 相对 base 恶化 < 5% |
| 安全 | 每个 session 的跌倒、安全违规、回滚、拒绝更新次数 | 全部记录，不删除 |

- 统计单位是"一个地形实例上的一次独立学习 session"，不是回合或控制步。
- 任何结果表都必须同时给出：base 在同一批实例上的结果、训练期指标、评测期指标。"探针""验证"等名称必须与配置中的 `evaluation_kind`、种子一致。
- 参考功效（精确 McNemar，α=0.05，按实例相互独立估算）：完成率 0.2→0.6 时，20 个配对实例的功效约 0.62，30 个约 0.84；0.3→0.45 这样的中等差异，即使 100 个实例功效也只有约 0.54。因此 G3 用估计值和预设阈值做路线决定，不追求显著性；封存实验的样本数在 11 月根据开发数据的方差确定。

## 7. 待确认的决定

1. D1：主问题定为"在遇到的地形上适应"（本文建议），还是保留"训练后迁移到新地形"。

4. D3/D9（v2.1）：G3 增加无 critic 臂 D。G3 算力由 53 增至约 74 GPU 小时，G1 另需约 6 GPU 小时。
5. D8（v2.1）：结构化探索噪声会改变采样契约（`requested_gaussian_through_fixed_safety_v1`），需要新的协议版本。与此并列的另一种做法是保持白噪声、把变化率上限放宽到 0.06。本文不建议后者：09-18 审计已明确，不应通过放宽安全上限来掩盖问题。
