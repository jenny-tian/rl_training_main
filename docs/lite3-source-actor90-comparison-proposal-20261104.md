# 现有 90 更新模型的只读配对对比提案

状态：proposed，尚未批准，未启动。原数值试训因吞吐未达标而拒绝的记录保持不变。
本提案只允许该已保存候选进入只读效果诊断，不改变原 600 条/秒效率要求。

## 目标与已具备的结果

从源码 `67d92d7443491c8a2b05e453f7a7ad34eeb58759` 实际完成了 90 次 PPO 更新、
259200 条训练交互和 1800 次反向/Adam 步。全部损失有限、actor/critic 变化、
最终 actor 可加载；唯一拒绝理由是端到端吞吐 431.2859397893 条/秒，低于 600。
旧 G3 完整资格仍未取得；1884 步有限范围证据和真实 G4 的通过结果保留。

要比较的模型：

- 原始 model_1998.pt，SHA256：`87ec1cd3ab44079045d8da627c70b61e4918c22a715a21d5f7204acb73fbbc3c`。
- actor_update_90.pt，760457 bytes，文件 SHA256：`14d11c8b57392c3ac0ac1e08b26de1cc1254ee059d1f653172433df9a05bdf42`。
- 新模型为 actor-only 推理权重，没有 optimizer/critic 续训状态。

## 一次批准的执行范围

1. 不重跑 G1/G2/G3/G4，不重新训练，不再预留 PPO 预算。只调整资格衔接，使
   此特定候选能进入诊断；CPU 重新核对训练数值证据和上述两份模型哈希，原始
   numerics accepted=false、吞吐值和台账 failed 状态都保持原样。任何其他数值
   异常、模型变化或生产行为变化均拒绝启动。
2. 只消费原整包尚未使用的 compare 槽位，启动一个 GPU0 作业，不增加新槽位。
   120 环境、一个共享地形 bank row、六类地形/15 个 L1 条件。原/新 actor 各
   最多 2000 控制步，总计至多 480000 条只读诊断交互，PPO 更新和训练交互均为 0。
3. 两个 actor 使用相同几何、初始状态、分配和命令 `vx=0.3, vy=0, yaw_rate=0`，
   比较确定性均值动作，关闭 policy 观测噪声。必须核对实际初始状态哈希及分配
   相同；生产安全、扫描有限性/命中归属等原检查保留。
4. 保留原限制：启动 120 秒、GPU 作业 1800 秒、清理 15 秒，GPU0 至少
   12288 MiB 空闲，磁盘至少 32 GiB。硬错误或验收失败停止，无自动重试。
5. 交付 120 对首回合的逐条件原始指标、完成数、前进距离、横漂、姿态和速度
   RMS 误差，以及 CSV/PNG 对比。条件样本数不假设每格相同，明确报告各格分母，
   汇总使用条件等权。完整结果出来前不声称新模型优于原模型。

该对比属于固定几何和初始状态下的配对诊断，不授予正式选模、独立地形成功率、
完整 G3 或训练吞吐资格。run2/run3、midpoint/pilot、额外训练及 GPU 重试均不包含。
执行完成或停止后统一详细汇报，再由用户批准后续阶段。
