# 下一阶段提案：首轮训练模型与六家族效果对比

状态：`proposed`，`user_approved=false`，2026-11-04。

本文件是范围和预算提案，不能作为运行清单。用户当前只要求停止当前 G3、先看
合并方案。修复、CPU 实现、新 GPU 运行和 PPO 训练均等待用户同意。本提案替代
后续每个准备/测试/归档小步骤各自成为阶段的推进方式；已发生的失败和历史预算
不改写、不退还。

## 交付目标和阶段边界

一个阶段交付一个可加载的新 checkpoint、90 次真实 PPO 更新记录和训练曲线，
以及原模型/新模型在六家族全部 15 个 L1 条件下的同条件对比。必要的修复、定向
测试、G3/G4、运行、归档及提交都属于阶段内部工作。获准后按依赖顺序推进，在
批准范围内报告内部里程碑，无需每个小步骤再次申请。任何硬停止、预算超限或
范围外工作均停止；本阶段未完成时明确报告直接阻塞，不能以测试数量代替模型。

90 次更新是首轮数值试训，验证训练能真实推进并给出早期效果，不保证六类地形
已学会。训练成功后再以每个条件的进步/退化决定下一轮；后续 midpoint/pilot
续训和正式选模不在本阶段内。

## 阶段内工作

1. 修复直接阻塞：先用已有数据做 CPU 分析，定位扫描非有限值检查与相关状态
   更新的问题。为首次异常补齐 sensor/env/ray/field、更新年龄、root/origin
   及 reset 前后的有限性证据，避免再只得到通用错误。保留有限性、扫描归属、
   跨环境接触、实际越界等硬停止条件，不用填零、跳过异常或删除检查使其通过。
2. 压缩证据处理的 CPU 开销：测量序列化、复制和压缩的耗时，优先批量/二进制
   无损编码；独立解码仍须还原全部原检查输入，不能靠减少物理步、地形条件或
   接触覆盖来提速。只对改动及相关拒绝路径做必要测试，完整回归放在最终稳定
   版本上执行，运行时不反复开启整套回归。
3. 必要时执行一次有边界的定位运行，随后最多一次完整 G3 v2。沿用 120 环境、
   一个共享 bank row、原冻结 actor 加 std1 的固定 seeded 噪声、0.3 m/s 命令、
   2000 主步加 1 恢复步和 8004 个物理子步。全环境接触正控制、Flat 9m 加 50
   稳定步和完整独立证据验证仍需通过；旧 actor 其他地形失败可记录/reset，
   不要求它先学会所有地形。修复后如 G1/G2 指纹或行为资格不再适用，使用
   下表预留的一次 G1 和一次 G2 复核，不能沿用失效资格；复核失败即停止。
4. 执行一次 G4 collection：48 步预热加 240 步测量，生产安全检查保留，关闭
   逐物理子步重型归档。提议沿用 600 transitions/s、reset p95 不超过 1 秒
   的门槛；同时报告实际样本数、reset 比例、启动时间和显存。
5. 接通首轮有界数值试训并执行一次。现有入口已经有 PPO、预算取整、预留和
   监督主体，但 `cumulative_training.validate_evidence` 同时要求正式选模
   protocol lock 和完整指标采集资格，不能把当前入口称为已经可直接训练。
   本阶段建议新增专门的数值试训授权类型，将它与正式选模依赖分开；保留
   G1/G2/G3/G4 collection、真实有限性与安全、源码/模型指纹、整笔预算预留、
   无自动重试和更新验收。不得伪造任何 qualified 收据。原正式选模入口的
   条件保留，数值试训产物不授予正式选模或技能资格。
6. 独立加载新 checkpoint，核对真实更新数、有限 loss/参数、actor/critic
   变化和计费。记录训练期间采集、PPO 和持久化合计吞吐，G4 end-to-end 在此
   才能判定，达不到门槛就保留未通过结果。
7. 一个对比作业内分别运行原 actor 和新 actor。每个 actor 最多 2000 控制步，
   120 环境、同样的初始分配/几何/命令、确定性 actor 均值；每个环境只将首个
   回合纳入配对表，超时和失败保留。全部实际推进交互单独计数，不因只分析
   首回合漏计。计划共 120 对，逐条件数量沿用已登记的分配块（并非每条件
   等量），比较时逐条件列出且使用条件等权汇总。报告完成数、前进量、横漂、
   姿态和终止原因；这是固定几何的诊断对比，不是独立地形成功率或正式选模。

## 拟批准的明确预算

GPU0，可共享，启动前可用显存至少 12288 MiB。七个作业槽位顺序执行，每个
最多一次；定位和 G1/G2 复核若不需要则跳过，不能将空余槽位改作其他重试。
先完成可选定位和最终修复，再冻结用于资格复核及后续训练的版本。源码每次运行
前提交、推送并核验远端，冻结实际清单、依赖、模型、seed 和证据格式；用户若
批准本整包范围，清单冻结属于阶段内部动作。

| 作业 | 最大实际交互 | GPU 子进程墙钟上限 | 训练更新 |
|---|---:|---:|---:|
| 可选扫描定位，最多 600 控制步 | 72000 只读 | 900 秒 | 0 |
| 必要时重做 G1，1 个零动作控制步 | 120 只读 | 240 秒 | 0 |
| 必要时重做 G2，4 个零动作控制步/4 批 reset | 480 只读 | 240 秒 | 0 |
| 完整 G3 v2，2001 控制步 | 240120 只读 | 1800 秒 | 0 |
| G4 collection，48+240 控制步 | 34560 只读 | 900 秒 | 0 |
| run1 numerics，120×24×90 | 259200 训练 | 900 秒 | 90 |
| 原/新 actor 对比，各最多 2000 控制步 | 480000 只读 | 1800 秒 | 0 |

GPU 作业墙钟上限合计 6780 秒（113 分钟），包含各自启动和关闭，不含 CPU
实现/测试和独立复核；这属于硬上限，不能当作交付时间承诺。各作业启动上限
120 秒、清理宽限 15 秒（清理宽限另计）。完整 G3 独立 CPU 验证另限 1800 秒；定位作业仅做
失败证据核对，不授予资格。最终方案和冻结清单必须遵守这些上限，若实现无法
满足则在启动前报告，不能自行恢复旧 7200 秒上限。

完整 G3 在前 64 个主控制步后检查累计速度：按当时速度预计无法在 1800 秒内
完成时立即退出，保留证据，禁止继续等待到超时。这个检查不证明后续不会变慢，
墙钟监督始终保留。独立 CPU 验证失败、G4 collection 未通过或训练验收失败均
停止后续作业。新异常不可通过不断扩展测试/重跑来消耗整阶段。

只读交互上限合计 827280 条，和 PPO 学习预算分开报告。
训练从原始登记 actor 均值、std=1、全新 critic/optimizer 开始。历史 run1
已计费 384 条，新增上限 259200 条后累计 259584，小于硬上限 262144，剩余
2560。保留现有整笔预留规则：训练启动前一次预留全部 259200 条，失败或部分
运行也不自动退款或重试；运行前明确报告预留，当前阶段没有预留。run2/run3
不消费，不自动进入 midpoint/pilot。

压缩事件/解压事件上限继续不超过 16/64 GiB，控制记录 4 GiB、运行日志
512 MiB、磁盘余量至少 32 GiB。新编码必须有完整性哈希和无损解码验证。
大数据保留在本机持久证据目录，仓库保存文件索引和哈希，不反复推送大日志。

## 验收和汇报方式

模型交付至少包含：原始输入引用、新 checkpoint 路径/SHA、独立加载结果、
90 次更新及 259200 条实际学习交互收据、预算前后记录、loss/reward/学习率等
真实训练曲线、15 条件对比 CSV/图表，以及继续训练或修复的具体建议。没有
达到模型验收就明确标为阶段未完成，不以准备工作替代结果。

阶段内部在阻塞修复明确、G3/G4 通过、首个真实更新、模型保存和对比完成等
里程碑汇报。每次说明实际交付、还差什么、下一步；不为无关的测试数量计进度。
完成后提交/推送到 `jenny-tian/rl_training_main` 私有仓库并核对远端一致。
