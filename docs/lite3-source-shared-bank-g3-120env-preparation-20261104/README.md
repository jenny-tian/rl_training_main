# 120 环境 G3：CPU 接入与未批准运行方案

本阶段只进行 CPU 实现、验证和运行方案准备，没有查询 GPU、启动 Isaac Sim 或
GPU 任务，没有新增真实 Source 交互、训练或 PPO 更新。真实 G3、G4 和正式训练
资格仍未取得。真实运行需要用户另行单独批准。

前置证据固定为已通过的
[120 环境 G2 v2](../lite3-source-shared-bank-g2-120env-v2-runtime-20261104/README.md)，
包括完整 G1 120→60→32→16 链，以及原策略的
[独立 Flat 安全前提](../lite3-source-policy-prequalification-flat-20261029/README.md)。
Flat 前提使用同一 checkpoint、0.3 m/s 命令，1514 步前进 9.295170 m，保持 50 步，
无权重更新或 PPO。该旧记录只覆盖基础策略的一个独立 Flat 回合，不证明新 G3
的带噪声并行表现。其余地形的旧任务失败继续作为学习基线，不要求全部先成功。

新增六个生产文件，原 G1/G2 的 243 项输入逐字节不变，总输入数为 249，已安装
依赖仍为 51 项。新增模块均不在导入时启动仿真：

| 文件 | 作用 |
|---|---|
| source_scan/scale_motion.py | G3 固定契约、G2 与 Flat 前置锚点、独立批准检查 |
| source_scan/scale_motion_evidence.py | 有界无损压缩日志、分块哈希、运动差分和重置后坐标重建 |
| source_scale_motion_collection.py | 冻结 actor、噪声动作、终止前指标与完整采集循环 |
| source_scale_motion_probe.py | 批准后建立真实场景，核对全刚体 guard、命令和接触报告 |
| source_scale_motion_supervisor.py | 父子输入核对、GPU0/磁盘门槛、超时、进程组清理及独立 CPU 验收 |
| source_scale_motion_validation.py | 流式重建接触、运动、扫描、重置、动作和 Flat 完成证据 |

G3 的目标是限定窗口内的运动隔离与证据完整性。跨环境接触、真实碰撞包络越界、
非有限值、错误分配/扫描归属、缓存污染、接触容量饱和和证据缺失均停止。普通
任务完成、安全/姿态/非足端接触失败、预测边界终止或任务 timeout 记录后自动
重置并继续；实际已经越界或失去有效状态仍属于完整性故障。

读取真实适配器的重置前回调，继续使用 G2 的新鲜接触基准和逐项相等检查，重置
后对选中环境的上一次位置/速度重新建立基准，避免把地形切换造成的位置跳变计入
运动速度或加速度。逐物理步记录所有 17 个刚体的位姿、速度、位移、有限差分
加速度、当前与预测边界、扫描和恢复 ID。这里的差分测量不构成连续时间安全证明。

| 步数范围 | 控制步 | 物理子步 | 只读诊断交互 |
|---|---:|---:|---:|
| 主运动段 | 2000 | 8000 | 240000 |
| 末尾恢复段 | 1 | 4 | 120 |
| 总计 | 2001 | 8004 | 240120 |

额外一控制步用于观察主段最后一个控制步发生重置时的首个物理恢复步。所有主段
重置都必须获得恢复记录。恢复段自身最后产生的新重置单独列为
deferred_final_recovery_ids，不授予其后续恢复资格，也不自动追加更多控制步。
这是对原 2000 控制步草案的明确修订，新的总预算须随运行提案一起批准。

策略为原始只读 45→512→256→128→12 ELU actor，checkpoint SHA 为
`87ec1cd3ab44079045d8da627c70b61e4918c22a715a21d5f7204acb73fbbc3c`。
不构造 critic、optimizer 或 PPO，不保存新权重。使用 float32，关闭 TF32 和
混合精度；单独的噪声发生器 seed=132001、标准差=1.0。环境/几何/sampler seed
为 130001/30000/131001，reset_state_id=40000 仅为登记标识，不重新播种全局 RNG。
命令固定为 [0.3,0,0]。安全过滤及原终止规则保留，动作投影可记录，执行前 pause
会停止。保存策略输入、actor 均值、噪声和最终动作；CPU 重新计算 actor 并核对
动作加法，前后权重哈希必须一致。CPU 随机流不被当作 CUDA 随机流的替代品。

验收要求主段覆盖全部 15 条件，并至少有一个 Flat 回合从本次运动证据中完成
9 m 和连续 50 步稳定保持。终止前进度必须与最后一个物理帧一致，hold 必须逐步
重算；终止 ID、原因、terminated/truncated、timeout、观测和重置后年龄互相一致。
所有 120 个环境至少记录一次超过 1e-4 N 的地面法向力点，作为接触报告正控制。
该阳性控制不单独证明长期承重或全部地形技能。其他普通任务失败不阻塞完整性
采集，但缺少本次 Flat 完整证据会拒绝 G3 验收。

每个接触子步仍检查完整 2040×2064 矩阵，包括只有力而没有点的配对；只存非零
并集和有效点，保留完整数组 SHA。独立 CPU 解码验证点/配对/net 重建、跨环境
零值、容量和全部子步。详细点容量固定 1048576，不自动扩大。

日志采用可逐条读取的多成员 gzip JSONL，数值保持原始 JSON 精度，分别记录压缩
与解压后的 SHA。接触、运动、原生 reset 快照及终止记录均保留；没有抽样省略。
写入前同时检查原始字节、落盘字节和单条记录上限。事件和步骤文件哈希按 1MiB
分块计算，G3 单独使用流式步骤持久化，不修改原 G1/G2 writer。

资源估算来自真实 G2 16 帧/四批数据，按每个控制步最多一次全环境重置、每个新增
差分/重建数值最多 32 字节文本估算；在类似接触活动下，约需 31583571998bytes
未压缩事件。按 G2 四个恢复控制步的时间外推为 4396 秒，约 73 分钟。两项都不是
G3 实测或最坏情况保证。接触点数量可能增长，压缩率也不保证；任一硬上限到达
都会停止并保留已有记录。旧草案 900 秒/2GiB 不再作为本次候选预算。仿真和验收
各自有截止时间，均不自动延长，不重试、不续跑、不换 GPU 或扩大环境数。
本阶段没有测量 G4 稳定期吞吐，不能用这项重日志估算判定训练性能。
