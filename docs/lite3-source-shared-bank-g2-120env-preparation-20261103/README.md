## 固定流程

场景仍为 120 环境、1 行 shared bank、六家族/15 个 L1 条件。环境/几何/sampler
seeds 分别为 130001/30000/131001，状态 ID 40000 仅为记录编号。不加载 actor，不
构造 PPO，动作均为零，不访问 Development/Sealed 反馈或选模。

| 批次 | 直接 reset 的环境 | reset 数 | 随后的恢复控制步/物理子步 |
|---|---|---:|---|
| 1 | `[0]` | 1 | 第 1 步，物理子步 1–4 |
| 2 | `[1,17,119]` | 3 | 第 2 步，物理子步 5–8 |
| 3 | `0,2,...,118` | 60 | 第 3 步，物理子步 9–12 |
| 4 | `0,...,119` | 120 | 第 4 步，物理子步 13–16 |

共 4 次 reset 调用、184 次环境 reset、4 个零动作控制步、16 个 5ms 物理子步。
物理推进合计 80ms，完整成功时为 480 条只读诊断交互，训练交互和更新均为 0。
直接 reset、forward 和缓存刷新不计作额外物理推进。初始 120 张票加 184 张新票
共 304 张，应有 2 个完整登记配额块及 64 张尾块；尾块按实际回放计数。

## 实现和独立验收

- 新增 scale_reset 契约，以及 source_scale_reset_probe/supervisor/collection/validation
  四个独立工具。父子进程必须显式选择 120 环境；批准检查先于 Git、GPU 和仿真。
  清单严格比较嵌套 JSON 类型和值，布尔 reset ID 也不能代替整数 ID。
- 绑定已通过的 120 环境 G1 真实归档，固定其 SHA256SUMS 和 review.json 的 SHA，
  再核对全部文件及 60→32→16 前置链。G1 执行提交为 a455b59，归档提交为 f99f7eb。
  旧归档、已批准清单和数据未改写；其支持力和训练资格仍保持原范围。
- 每批记录 reset 尝试、实际 after、检查完成三个阶段。快照包括 row/column、
  origin、root、关节、episode、动作、命令、观测历史及 pushes、传感器时间戳/
  缓存，以及过滤器和 lifecycle 状态。实际存在的历史项由 probe 枚举；没有历史
  时明确记录空列表，不能用孤立 pushes 或缺失字段伪造完整快照。
- 独立验收逐项恢复所有快照，核对 shape/dtype 与无损值。只在 reset 边界断言
  未 reset 行逐值不变，检查选中环境缓存、历史、动作和运行时状态清理，并核对
  spawn origin、分配票顺序和全量当前分配。物理推进后的正常变化另行检查。
- 每批恢复的第一个物理子步必须记录准确 recovery IDs，其余三个子步必须为空。
  全部 16 帧接触独立重建、完整数组 SHA、17 次运行时 stage/backend 记录、刚体
  包络、扫描归属和年龄、4×120 行动作/指标、意外结束及进程清理均独立验收。
- 指标中的 step 是逐环境 episode 年龄；未 reset 环境继续累加，被 reset 环境
  从 1 重新开始，不能用全局控制步号代替。
- 稀疏采集器新增显式 G2_reset_recovery 范围，只允许 120 环境、4 个恢复控制步、
  16 个物理子步，并保持支持力资格为 false。默认 G1 的无支持力例外仍只允许
  1 个控制步/4 个子步，正式 positive-control 路径没有放宽。

120 环境 G1 只有初始化 20ms 的零力记录。G2 仍不提前承诺支持力阳性；即使限定
reset/首步检查成功，也不授予稳定承重、长时运动隔离、G3/G4 或训练资格。该模式
没有 checkpoint 调度状态恢复，也不能证明训练 checkpoint 可无缝续跑。

## CPU 验证、发现和修复

完整登记 CPU 回归 **929 passed，0 failed，0 skipped**，覆盖 26 个测试文件，
其中新增 G2 检查 105 项。pytest 耗时 735.78 秒，外层计时 738.73 秒；525 条 warning
来自已安装 PhysX 文档字符串的既有转义提示。原始命令、环境变量、JUnit 和日志
均保存在 raw 中。
测试使用 CUDA 不可见、关闭 pytest 插件和 CPU 单线程配置，没有安装或升级依赖。
整目录历史缺失 scripts.tools.runtime_progress 的收集问题未改动，结果限于登记文件。

CPU 联调发现并修复了两处问题，保留了原始失败证据：

1. 首步推理模式产生的过滤器内存，在第二批 reset 的普通模式原地更新时报错。
   现在同一个推理模式上下文覆盖四批 reset 和恢复控制，退出后正常恢复模式。
2. 初次 190 项针对性检查为 189 passed、1 failed：修改记录头 stage_id 后，其余
   后端字段仍一致，旧检查未拒绝该矛盾。已增加记录头与采集 stage 的关系检查，
   没有放宽验收。修复后该故障和部分写入回滚的 2 项定向复测通过，随后完整回归通过。

新增的事务测试调用真实地形分配适配器，在 origin 部分写入后注入异常，确认
row/column/origin 三个缓冲回滚、旧 allocator 不替换，下一次分配从原票据继续。
该测试隔离了无关 USD 图审计，物理碰撞图由既有 G1 证据及 G2 独立验收检查。
事务测试首版误用了 API 参数，已修正测试设置，初始失败日志也保留。本例证明地形
分配写入事务，不授予原生资产 reset 事件任意失败后的恢复或继续运行资格。

故障检查覆盖 env119 非选中状态污染、历史/pushes/接触缓存/时间戳未清理、spawn
异常、票据和尾块篡改、恢复首步遗漏、frame 缺失/重复、内部 force 损坏、扫描错误、
指标 episode 年龄错误、运行时 stage 矛盾、未批准清单、超时和空退出。即使重算外层
文件 SHA，内部关系损坏仍会被拒绝；CPU 假子进程不启动仿真，不写生产预算。

raw/cpu_example 是明确标记的合成 CPU 数据，复用已安装 Lab step/PhysX getter
函数体及实际 Source 运行时，底层缓冲、状态和观测历史由 CPU 构造。它有完整四批
流程、16 帧和票据回放，只证明采集与验收逻辑；其中 cuda/backend 元数据及正接触力
不能作为 GPU 或物理资格。无支持力样例也通过限定范围验收，支持力资格保持 false。
