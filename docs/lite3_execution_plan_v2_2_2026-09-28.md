# Lite3 在线地形适应执行方案 v2.2

日期：2026-09-28。制定依据：[跨领域文献复核](lite3-literature-and-algorithm-review-2026-09-28.md)、[v2.1 审核](lite3-plan-audit-2026-09-28.md)、当前源码和 G0 基线结果。

本文件作为后续实施与实验安排的基准，替代 [v2.1](lite3_online_adaptation_plan_v2_2026-09-24.md) 中冲突的算法门槛、预算、排期及路线选择规则。历史数据仍保留。**本文规定要做什么，不表示这些改动已完成，也不表示长训练已经启动。**

## 1. 目标、交付与不变条件

**主问题：**一个已经在平地学会运动的 Lite3，在遇到新地形后，能否通过有限在线交互得到冻结后仍能稳定完成该地形的策略？

主要交付是可重现的适应算法、公平比较结果、消融和失败分析。跨地形迁移与返回平地后的能力保持是次要终点。先以 rough_4cm 为主，再用台阶验证；不把“所有未知地形通用”作为首轮目标。

固定条件：base checkpoint 权重不可写；统一赛道完成定义、速度任务、deadline、动作尺度和安全上限。LoRA 只改低秩增量；SAC 只改适配器/价值网络。主比较先限定相同的本体信息权限，高度扫描另设后续输入消融。暂停高度扫描 teacher，不把合格 teacher 设为 SAC 或低维搜索的前提。

研究路线有三条，独立晋级：

- **A：修复后的 LoRA-PPO。**验证低秩梯度适配是否有效，提供必要强对照。
- **B：修复后的 Residual SAC。**继续投入，验证目标域经验和稳定价值学习能否改善当前结果。
- **C：结构化低维修正。**先用无 critic 搜索检验动作接口有没有可用收益，再考虑 latent SAC、自模仿和额外残差。

拟研究的机制是“在状态化安全投影下保留有效探索方向，并把探索收益变成确定性控制”。它是**待验证假设**；LoRA、latent、SAC 或上述组合本身不声明原创。

## 3. 算法形式和最小实现

### 3.1 共用执行链

```text
基础动作 μ₀(o_t) + 适配请求 δ_t
                 ↓
统一安全映射 P_safe(·; s_filter,t)
                 ↓
实际执行动作 a_exec,t → 环境 → 轨迹/replay
```

安全映射依赖上一执行残差、暂停/回退状态等；这些状态必须记录并正确 reset。不能把多个请求映射到同一执行动作误解为多个独立有效探索方向。

requested-action PPO/SAC 与执行后的监督目标分开定义。不能用执行动作直接替换请求动作去计算原 Gaussian 的 log-prob。无论使用哪种适配器，都必须保持 base 的上一动作输入语义一致。

### 3.2 C 路线：先验证结构，再学习状态依赖

第一版采用：

`δ_t = L ⊙ tanh(B(h_t) z)`，`a_exec,t = P_safe(μ₀(o_t)+δ_t; s_filter,t)`。

L 为 G0 锁定的逐关节残差幅值上限，不为新方法单独放宽；z 为低维参数，B 为固定/已版本化的行为映射。z=0 必须回到共同 frozen base。

执行顺序：

1. **C0：回合固定 z。**先验证 2 维行为基；每回合搜索一个 z，回合内只有 B 随合法观测变化。避免一开始引入跨步采样概率、宏动作价值和 replay 版本问题。
2. **C1：4 维固定基。**仅在 2 维有收益或存在明确容量不足证据时增加。随机正交基作为同维对照。
3. **C2：状态条件 z=fθ(h)。**从有效轨迹的原始 z 标签蒸馏，或用 latent SAC 学习；两种方式分别登记，不同时改。
4. **C3：Bz＋额外残差。**只有 steering-only 有效但剩余失败有稳定模式时，才采用 USR 启发的组合。

首版行为基候选是前/后腿的摆动期屈伸修正。先用 Lite3 关节映射及运动学核验符号，幅度使用归一化动作单位；不直接写死未经核对的弧度值。若没有合法且可靠的相位输入，先用固定关节协同基，明确不称“抬腿策略”；不以仿真接触真值伪装纯本体感知。

## 4. G0：统一基线、记录和预算（最高优先级）

预计 2–4 个有效工作日；结束条件优先于日期。G0 没通过时，只允许诊断，不启动以学习收益为目的的大规模比较。

### G0.1 定位 101/109 runner 差异

涉及：`train_lora_ppo.py`、`play_online_adaptation.py`、`run_rocky_road_multiepisode.py`、`ppo_runtime_config.py`、`rsl_rl_compat.py`、`isaaclab_adapter.py`、`safety.py`、`ppo_safety.py`。

步骤：

1. 锁定 base SHA、代码 commit、物理/控制 dt、关节顺序、动作缩放、reset、terrain mesh/hash、GPU/软件版本。比较完整解析配置，不只比较任务名。
2. 在完全相同的保存观测上，比较两个入口的 base 原始输出、clip 后动作、零适配输出、安全处理结果。
3. 对同一预定动作序列比较环境状态、奖励和终止；区分控制器差异与仿真差异。
4. 检查 previous_action 指的是请求、clip 后还是最终执行动作，以及 reset 后历史和 limiter 状态是否清零。
5. 先用 101/109 各跑两个入口的固定条件诊断；找到原因后，再复跑五个调试地形。总诊断预算首轮上限 60,000 环境步，超过前写明已排除项及追加目的。

验收：离线 float32 base/action 比较先以 max_abs≤1e-6 为目标；不要求跨进程 PhysX 轨迹逐位一致。重复运行允许数值漂移，但不得有未解释的动作契约或配置差异。若物理随机性仍导致成败波动，正式实验统一使用一个经验证的执行核心并报告重复分布；不调参强行凑历史结果。

产物：`runner_parity_report.json`、配置差异表、最早发生差异的 transition、共同 frozen-base manifest。base-only、LoRA 零增量、SAC 零均值、C 路线 z=0 都通过同一执行链。

### G0.2 补齐两条路径的轨迹和恢复

复用 `step_trajectory.py`；接到 `play_online_adaptation.py`，核对 `train_residual_sac.py` 这个独立入口是否也需要同样支持。

最少字段：obs/current_frame/history 及字段版本；base/mean/request/executed action；上一执行残差与安全状态；reward 分项；动作前和 reset 前后继状态；physical terminated、task terminal、collector cutoff、bootstrap mask；episode/session/策略版本；z/decoder 版本（如适用）；reset 原因与步数账本。

验收：从 trace 重算 step_count、return、max_x、失败类型与 summary 一致；断点恢复保留预算、replay、optimizer、alpha、随机数、候选选择状态；独立 session 则全部重置。异常退出文件必须标记 interrupted，不冒充完整回合。

float16 日志不用于 1e-6 等价验证；G0 parity 的短轨迹另存 float32。历史日志缺少完整观测时，不补造观测或拿它做精确反演。

### G0.3 统一输入权限、时间与终止契约

输出 `observation_contract.json`，按字段列出 actor/critic/safety/reward/evaluation 的来源和可用性。base 原输入固定；适配器可使用的本体历史、安全记忆明确列出。SAC 的历史信息若多于 LoRA，只能解释为系统比较；若要主张优化器优势，必须补输入相同的消融。

初始协议使用实际已实现的接触/速度等输入，逐项标注“传感/估计量”或“仿真真值”，不能只写 proprio 就默认可部署。新增接触相位必须满足同权限条件，否则单列 privileged 臂。

默认主任务为 finite-horizon：成功、失败、2000 步任务 deadline 均结束本任务回报；纯采样预算 cutoff 则不是任务终止。先核对现有吸收成功奖励/提前停止公式，确保返回值与定义一致，不能把完成后未执行的奖励当作已观测 MC。若原协议采用别的语义，用明确的新版本统一迁移，所有旧对照重跑。

reward 先保持同一任务定义；不同时把奖励改成剩余距离。奖励正比例缩放需记录单位，并同步检查 SAC 温度、正则系数和价值尺度，否则不是纯数值等价变化。

### G1-A：LoRA-PPO

1. 固定 actor 与采样策略，在两个调试地形各收集至少 6 个完整回合，最多 24,000 步；每地形 4 回合拟合、2 回合验证，按完整回合划分且使用不同扰动/噪声种子。它是开发诊断成本，不作为正式 session 免费数据。
2. 先只训练 critic，分别比较常数、仅时间特征基线与学习价值函数。报告目标方差、归一化 RMSE、偏置、EV，以及接触/进度阶段误差。目标方差接近零时 EV 标为不可解释。
3. 回报采用完整任务回报；collector 截断单列。λ=1 不等于完整 MC。首轮不加 HL-Gauss 或分布式 critic。
4. 正式试跑的 actor 预热默认为前 4,000 目标域步；数据由 frozen mean base 产生，critic 拟合，actor 不更新。拟合完成后丢弃旧行为样本用于 actor 更新的资格，actor 只用新 on-policy rollout。
5. rollout 先比较现行 256 与 1024 控制步；跨真实结束切断 GAE，rollout 未结束时正确 bootstrap。只改变一个因素。
6. actor lr 先保留解析配置中的现值；若实际近似 KL 长期很小且价值诊断改善，再试现值的 3 倍（例如现值 5e-5 则试 1.5e-4），保留原 KL/梯度上限。rank 首轮不改。
7. base critic 特征迁移作为备选，需要输入字段/归一化契约吻合；不直接复制旧输出头宣称同奖励价值。

开发最多 2 个候选配置，每个在 2 个地形 × 2 个独立适应种子上确认；候选选择记录所有成本。价值改善仅支持继续试跑，**冻结任务表现**决定路线是否晋级。

### G1-B：Residual SAC

1. 同样以目标地形 frozen mean base 采前 4,000 步 replay；奖励按当前任务重算。平地数据可用于保持，不承担目标域 Q 预热角色。
2. 区分“采 replay”与“只更新 critic”。warmup 结束后首版最多做 1,000 次 critic-only minibatch 更新，再开始 actor/alpha 更新；这些更新计计算预算。具体 replay 条数不足时拒绝启动，不反复复制几条数据凑 batch。
3. 先保留 twin-Q、n=1、现行网络；确保 soft Bellman target、tanh/动作缩放下 log-prob、target_entropy 和 alpha 的坐标一致。不得将 latent 的维数直接沿用旧 12 维动作的 entropy 目标。
4. 保留 HistoryEncoder 现有 LN；单独试 **Q 主干 LN**。先 UTD=1，actor 每 2 次 critic 更新一次；如果更新调度与现行不同，分开记录对照。再根据价值稳定性试 UTD=4，避免同时改动 LN、UTD、n-step。
5. n=3 为后续候选：先审查 `nstep.py` / `sac.py` 中中间奖励、实际 n、gamma^n、终止和熵处理；需说明 off-policy 中间动作导致的偏差。不能仅切参数就称“复现 ResFiT”。ensemble>2 暂缓。
6. Q 验证优先固定策略的 soft target 残差、偏置和尺度诊断；若与多步 rollout 比较，保持策略/alpha 固定并计熵。仅 base 的确定性轨迹不提供随机 SAC soft-Q 的直接真值。纯 reward-only MC 不能作为 SAC Q 的同尺度目标。

开发最多 2 个候选配置，预算与 A 相同。SAC 无需等待 PPO critic EV 达某数值才运行；真实算法不同，不强求两者梯度更新次数相等，但记录计算成本。

### G1 共同验收

先通过数值/契约检查：无 NaN、无跨 reset bootstrap、无基线权重变化、恢复一致、严格冻结时 updates=0。预热/Q 诊断不过，先定位，不能靠增加长训练掩盖。

**工程晋级规则（非显著性结论）：**每路线在两个地形 × 两次独立 session、每 session 5 个保留起点上进行无探索评估。至少一个地形的平均完成率比相同起点的 base 增加 20 个百分点，且该地形两次 session 的增益方向都为正；另一地形不出现超过 20 个百分点的下降。通过平地保持与安全检查后可进入 G3。

若完成率无提升，但相对前进距离中位数提升≥10%、跌倒未增加，只允许一次登记过的救援修订，不宣称通过。以上阈值是有限资源下的继续/停止规则，不证明真实成功率达到某值。修好但无效的基线仍可保留为 G3 对照，不能因它较弱就从论文里删除。

## 6. G2：验证结构化探索和可用行为空间

预计 3–5 个工作日；可在 G0 之后与 G1 交错。先做两类诊断，不能把无学习的带噪声成功当成算法收益。

### G2.1 无更新噪声对照

两个调试地形，固定 base、相同 seed/reset 分布：独立 Gaussian、时间相关噪声（先选 AR(1)，ρ=0.9）、无噪声 base。每个噪声臂 2 个独立 session，每 session 最多 20,000 步；无噪声基线复用经验证的配对结果。

第一组匹配请求噪声 RMS；记录执行残差 RMS、频谱/自相关、投影比例、非足接触、进度和完成率。若两类执行 RMS 差异很大，再在独立开发数据上做执行量级匹配，不能看终点评估结果调噪声。

AR 状态在 reset 时清零；此实验不更新 PPO，故不偷用独立 Gaussian 的 PPO 概率。以后若加入 PPO，需实现带历史的条件似然和策略版本一致性后另测。

### G2.2 2 维行为基 headroom

先检验关节符号、z=0 等价、请求和执行单位、基本平地可行性。首轮 z 的每维只用 {-1,0,1}，归一化基列与 L 限制保证所有候选处于共同安全上限内。

每个调试地形：9 个固定候选各 1 个回合；按完成优先、归一化相对前进其次、较少安全干预再次的固定规则取前 2 个；在 3 个新的扰动起点重测两个候选及 base。每地形最多 36,000 步，两地形共 72,000 步，包含选择与复测。

headroom 初筛通过：某一候选在三个新起点上至少增加一次完成且不降低另外两次的进度，或进度中位数≥base 的 1.1 倍且不增加跌倒；再用另一组 3 个起点确认方向一致。确认成本另列，上限 12,000 步/地形。三次不构成统计证明，只决定是否投资 C 路线。

若通过，加入同维随机正交基及一个 4 维基作比较；若不通过，最多改一次基的物理定义。第二次仍无 headroom，暂停 C，不扩成 diffusion，也不继续堆维数。该结果只否定测试过的接口/范围。

### G2.3 C0 的首版在线优化器

采用可审计的回合级精英搜索，暂不同时引入 CMA-ES、BO、PI² 三套依赖：

- z 初始均值为 0，初始 std=0.3，限制在 [-1,1]；首轮包含 z=0。
- 每批最多 4 个候选；使用预先定义的起点日程，candidate 与更新结果全部保存。
- 按上述排序保留前 2 个，用精英均值更新搜索中心；保留 std 下限 0.1，避免一次好运立刻塌缩。
- 每批候选均从任务入口物理 reset，不允许从失败前快照无成本重试。
- 最终部署开发复测选定的 z；选择复测计入适应预算。预算不足完成下一回合时停止，不拿截断进度与完整回合成功直接排名。

该方法仅为低成本可证伪基线，不主张搜索规则创新；若噪声敏感、预算允许，再把 CMA-ES 作为后续明确消融。

## 7. 共用实验协议：把“20 回合”改成可比较预算

### 7.1 每个适应 session

- 主预算 **B=40,000 个实际控制 transition**，相当于最多 20 个满长 2000 步回合；提前失败时实际回合数会更多。每个环境实例的步数相加，不能把并行 32 个环境的一次 step 计成 1。
- 其中预留最多 8,000 步供候选选择/晋升探针；目标域 warmup 包含在其余 32,000 步内。未使用额度可按预登记规则用于采集；算法不得额外免费重测。首版 warmup=4,000，因此最多 28,000 步用于后续学习采集。
- 最终无反馈评测：同地形 10 个独立预定扰动起点；各方法与 base 共用起点。每 session 最多 20,000 步，单独记为 evaluation，不回放、不调参、不据此选择 checkpoint。
- 平地保持：5 个共同起点，每个最多 1000 步，单独预算最多 5,000 步。开发冻结评估首次可用 5 个地形起点节省成本，但 G3 一律 10 个。
- 每个 session 从相同 base、预登记适配器初始化和全新 optimizer/replay/normalizer/RNG 开始；不得沿用上一地形学到的状态。预训练模块/源平地数据固定哈希并单列离线成本。
- 初始探针检查点安排在累计交互约 10k、20k、40k；探针消费也占 B，因此按账本边界调度，不能实现为“先采满 B 再补探针”。最终保留候选在最终评测开始前写入 manifest。

用于晋升/rollback 的平地 rollout 也属于候选选择开销：在 B 内专门计 flat-selection，并报告其地形构成；纯最后的平地评测另列。如保持成本使用离线固定 anchor，记录离线样本量，不假装等价于实际平地保持验收。

对于无更新噪声对照，带噪执行表现是诊断；关闭噪声后的最终策略就是 base，不把它当另一种已经学习成功的策略。

### 7.2 开发地形和初态

1. 调试集：现有 101/103/107/109/113 以及旧封存种子；只用于工程与机制探索。
2. G3 开发池：先生成 24 个未用于调参的 rough_4cm 候选，只用 base 在每个实例 5 个筛选起点上评估；0–1/5 为操作性失败池 F，2–3/5 为混合池 M，4–5/5 为成功池 S，不宣称这些比例就是总体概率。
3. 优先取至少 8 个 F 作 G3，另取 4 个 M/S 测负迁移。不足时按预登记种子序列扩到最多 48 个；仍不足则记录任务存在的 ceiling 问题，不根据适配算法结果挑实例。
4. 筛选起点、适应采集起点、候选探针起点、最终评测起点四组分离；base 的最终评测也使用最终那组，避免按 base 坏运气筛选后高估改善。
5. 初态先采用 x/y 各 ±0.02 m、yaw ±2°，其余维度遵循同一 reset/settling；这是**待 G0 验证的起始范围**。出生碰撞/穿地必须按几何有效性规则统一处理，不得按成败选择性丢弃。验证后锁定范围再建立 F 池。

地形 seed 不等于独立适应 seed；每个实例至少做 3 次独立适应 session。报告结论限定为该失败池上的条件适应能力。

### 7.3 终点和停止条件

主要指标：每个 session 冻结后 10 个起点的成功比例；以地形为一级、session 为二级报告分布及 paired difference。次要指标：相对进度 `max(0,max_x−initial_x)/(goal_x−initial_x)`、跌倒/侧向越界/非足接触、目标速度误差、时间、动作平滑度和干预。

操作性平地保持：5 次无新增跌倒/硬安全终止，平均速度跟踪误差不比 paired base 恶化超过 10%；base 误差近零时使用 G0 锁定的绝对容差，避免不稳定比值。未通过的策略不能作为可部署候选，但失败结果仍保留。

NaN/Inf、base hash 变化、动作契约或预算失配立刻中止该 session，列为实现失败，修复后以新版本重跑。正常跌倒是任务结果；连续 5 个短于 100 步的跌倒触发 session 提前停止，计为失败并报告实际预算，不能从平均值中删除。

临床式/形式安全保证不在当前证据范围内；限幅、较少跌倒或 4/5 成功都不能表述成证明。

## 8. G3：路线决定实验

前置：G0 通过，A/B 已完成修复诊断，C 具有 headroom 才加入。预计 4–7 天排队/计算时间，取决于空闲 GPU 和实际吞吐。

首轮固定三类适应方法：A LoRA-PPO、B Residual SAC、C0 结构化低维搜索（若合格）。对照是同执行链的 frozen base；噪声机制诊断已有 G2，必要时只对最终探索形态补配对。

规模：8 个 F 地形 × 3 个独立 session × 至多 3 臂 = 72 个适应 session。

上限账目：适应 72×40k=2.88M 步；终点评测 72×20k=1.44M；平地评测 72×5k=0.36M，总计 4.68M，另列可共享的 base/筛选/迁移成本。按旧运行约 10–15 环境控制步/秒估算为 **87–130 GPU 小时**，再预留 30% 为约 113–169 GPU 小时；这是吞吐估算，不是完成承诺。新学习器速度需先用 smoke 校准。

只使用空闲卡，默认最多两张卡；不为了“同步”让同一 GPU 上多个 Isaac 进程互相干扰。A/B 调度独立，不能在等待某一臂时闲置另一条已可运行的路线。

路线选择规则：

1. 保留各臂全部成功/失败结果；实现失败先修复版本，不与旧版混成同一组。
2. 工程候选要求：相对 base 的总体冻结完成率提升≥15 个百分点，至少 5/8 个地形 session 平均增益为正，且平地保持通过；这是开发决策阈值，不是显著性声明。
3. 满足要求者先比较完成率，再比较失败/干预及计算成本。差距不足 5 个百分点、区间重叠大时保留两条路线，不预设“平局选 LoRA”。
4. 都没达到时，先区分“接口无 headroom”和“接口有 headroom 但学习失败”；不进入更长、更多重复的相同训练。

统计按地形聚类 bootstrap / 配对置换给出不确定性；同一地形内评测回合不当作独立训练样本。G3 主要用于估计与选路线，不报告未经设计的精确功效。

## 9. G4：只围绕一个有证据的机制做算法创新

预计 5–10 个工作日，选择顺序如下；不同时实现多个大型模块。

### G4.1 首选：状态化执行映射下的探索方向选择

触发条件：G2 确認大量请求变化被限速/投影抹去；简单时间相关噪声不能解释全部改善；C 的行为基已存在可复现 headroom。

候选实现：从当前 session 已收集的安全状态 h 出发，在安全映射的**副本**上计算各基方向 ±ε 的执行差分，度量哪些方向在当前状态仍有执行响应。ε 首个开发候选为 z 单位的 0.05；必须做局部稳定性检查。

`d_i(h) = [P_safe(μ₀+δ(z+εe_i);h) − P_safe(μ₀+δ(z−εe_i);h)] / (2ε)`。

聚合方向响应及别名相关性，抑制反复被抹去的方向；不对近零响应取倒数放大，不放宽原限幅，不把“动作能执行”当作“任务有收益”。正向任务证据仍来自计费环境交互。

安全副本的反事实计算不推进环境，单列计算成本；它不是回溯分支标签。统计只用该 session 允许的数据，更新时记录映射版本；首版可用固定小段预热数据后冻结该映射，避免 replay 非平稳。

最低消融：固定行为基、同维随机基、时间相关噪声、执行响应选择；匹配执行 RMS、总 B 和适配器容量。若优势消失，接受“平滑/量级解释已足够”，不声称新机制有效。

### G4.2 FlowDAgger 启发的成功修正蒸馏（有有效轨迹才启动）

从成功/高进度轨迹保存原始 z 和 requested/executed 动作。第一版对 z 做监督拟合并混合固定平地 z=0 anchor；这属于本项目设计，**不是 FlowDAgger 原论文的 50/50 数据配方复现**。拆分必须按回合，不能随机拆相邻步。

先比较固定 z 与状态条件 fθ(h)，均关闭探索；再增加执行一致性诊断。非光滑安全映射首轮仅用于验收，不未经处理直接反传。若单个 h 有互相冲突的成功 z，记录多模态问题，不强行以均值 MSE 表示所有走法。

当前候选策略产生新数据后再聚合；来自自主成功时称自模仿，不称专家 DAgger。若需要额外采集，依然使用同一 B 账本。只有闭环成功率改善才保留该模块。

### G4.3 USR 启发的补充残差（次选）

只有 C2 有效但存在稳定的表达不足时，加入 `g(h)r(h)`。比较 steering-only、residual-only、combined，以及同成本更大固定基。首轮不用额外蒸馏 critic，避免给小 MLP 增加没有明确收益的价值误差链。

若 latent 每 K 步采样一次，首个 K 候选=5（确认控制 dt=20 ms 后为 0.1 s）；采用宏步 replay：`R=Σ γ^j r_j`、`discount=γ^实际步数`，保存宏步内提前终止、z 和安全状态。next action/log-prob 按宏步决策频率定义；不能每个内部步重复计算同一次 entropy。这个实现通过专门目标测试后才能训练。

### G4.4 备选与延期项

PARTS 式状态触发仅在有可靠的可观测瓶颈判定时做一项消融，仍以完整赛道完成为终点。OSRAM 式指令调节只作为已有指令接口的备选，不通过放宽速度任务/deadline 得到“提升”。

M3 快照分支单列仿真特权上界，最多投入 2 个工作日验证恢复；需覆盖 root/joint、控制历史、接触/传感器、随机数和终止一致性。未可靠恢复则退出，不阻塞主线。Flow/扩散 base 重训、高度扫描 teacher、恢复策略大规模重训均非本轮必做项。

## 10. G5：跨场景、封存和论文证据

先在开发台阶池验证主方法；另在 4 个 M/S 开发实例与平地检验负迁移。最多两项关键消融：探索接口/时间结构；执行响应选择或蒸馏（根据最终方法确定）。不为凑创新数量堆更多模块。

长预算只在 G3 有收益后启动：40k → 80k → 最多 160k transitions，保存预登记预算点的固定候选。每个预算点的无反馈评估另列，不能据其结果回滚并继续训练却仍称无反馈。若 80k 未改善且失败机制未变，不自动延长到 160k。

封存流程分两层：

1. 锁定候选方法、超参、B、起点分布、筛选/接受规则、统计脚本和样本量。根据开发期地形/session 方差估计所需样本，不沿用仅凭边际成功率计算的 McNemar 功效。
2. 对不可变协议版本做哈希，以显式 namespace 生成新 terrain/reset/session seeds；从已使用集合排除碰撞。固定编号重试规则，不能反复换盐挑有利 seed。
3. **封存适应集不是禁止一切学习。**本研究主终点需要在新地形按锁定算法进行 B 步在线适应，允许这种协议内学习；禁止依据封存结果修改算法/超参。
4. 适应结束后进入该 session 的冻结评估：禁止梯度/optimizer/replay 写入，锁定 checkpoint，用独立起点测试。跨地形迁移单独做完全不学习的测试。
5. base 可按预登记规则筛选封存 F/S；记录筛选成本和所有候选，适配表现不可参与选地形。任何中途看结果后调参都使该批退役，另登记最终测试。

论文目标是“有可重现机制支持的方法改进”。若所有方法无可靠收益，交付边界/失败机制分析和开放实验协议；是否满足学校算法创新要求需另外对照培养要求，不能以负结果自动承诺达到要求。
