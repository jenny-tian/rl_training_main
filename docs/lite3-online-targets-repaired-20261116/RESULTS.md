# 回调修复验证：发现残差历史与零码对照不兼容

本次获批继续后，B 的短检查通过了上次出错的回调位置和 50 步站姿准备，已进入策略控制。随后触发 `zero residual changes a feasible base action`，按批准的接口失败停止条件结束。zero10100 短检查、正式基线、固定码搜索和参数更新均未运行。

## 原因与影响

现有 `SafetyFilter` 将关节限位后的动作与原基础动作之差写入 `_previous_residual`。这个差值同时包含两部分：基础动作自身越限所需的修正，以及学习残差的执行效果。下一步基础动作恢复可行后，残差变化率限制仍然使用此前总修正，导致零残差请求也可能带出一个额外动作。

代码路径是：基础动作越限 → 物理关节投影 → 总修正写入残差历史 → 下一步零请求经过变化率限制 → 基础动作可行但仍被改变。旧 `test_force_zero_residual_preserves_only_joint_limit_correction_memory` 明确保存了这种行为，因此属于旧过滤语义与当前零码对照要求不兼容，不能仅靠放宽检查容差解决。

这会污染零残差对照，妨碍区分基础策略、保护介入和残差带来的变化。本阶段必须先解决它，才能解释后续固定残差或在线学习收益。但不能据此断言它是历史基础 PPO 上阶或步态问题的原因：那些基础训练没有经过本次新接入的残差桥。

## 已完成的离线修复

新增独立 `CurrentModelSafetyFilter`，不改动历史 `SafetyFilter` 及旧实验。它沿用原来的物理限位、0.02 rad 余量、残差幅度、0.02 变化率、倾斜/高度/速度/接触保护和暂停恢复规则，仅调整下一步使用的残差历史：

```
旧历史 = 投影(基础动作 + 残差) - 基础动作
新历史 = 投影(基础动作 + 残差) - 投影(基础动作)
```

每步执行动作仍经过原过滤器的物理投影，完整基础修正仍记录；额外提供基础修正和学习残差效果两个分量。为避免浮点计算次序引入假残差，基准投影遵循原过滤器暂停/非暂停分支的计算顺序。非零请求主动切换为零时仍保留正常渐变，不使用每步清空全部历史的办法。

离线两步复现使用当前默认姿态/动作尺度和明确的合成关节边界：第一步髋关节归一化动作 8.02，投影后约 7.92。第二步基础动作和请求均为零，旧接口仍输出约 -0.08，新接口输出 0。第一次物理投影输出相同。这是代码机制复现，不是本次仿真失败帧的数值。

补充了零码/非零码混合批次、逐环境重置、持续限位穿越、随机残差边界、原保护分支、正常渐变和快照复制测试。候选修复已经实现并通过离线检查，尚未接入运行中的仿真，也未获验证通过结论。

旧 EA `shadow.py` 会直接构造旧过滤器，不能用于新历史语义的快照。候选修复提供独立 `from_snapshot`，下一次接入时必须统一实时过滤与影子评估的过滤器类型；当前尚不能给出 EA 在 B 上有效的结论。

## 数据记录缺口

本次保存了配置、几何、准备后的初始状态、错误栈和进程执行记录。但原收集器只在正常结束时写入完整轨迹；失败后内存中的轨迹没有保存，无法确定失败的精确控制步、环境编号、关节和偏移量。不得从 77.96 秒墙钟时间反推控制步数，也不能用合成复现冒充现场数据。

新增异常现场保存工具及测试，可在进程仍存活时从异常栈取得已有轨迹、当前决策、过滤器历史和部分结果。下一次接入后先保存再退出；不会为补这次数据额外运行仿真。现有丢失数据无法追回。
