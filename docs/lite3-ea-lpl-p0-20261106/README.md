## 偏离与异常

1. GPU0、GPU1 被其他用户的训练占用，空闲显存约 7.8 GB，低于 12 GB 的启动门槛。用户决定改用 GPU2。每批同时跑两个运行，单个运行显存峰值约 2.9 GB，两个同时约 5.7 GB。
2. `git worktree add` 不会初始化 `deep_robotics_model` 子模块，第 1 次冒烟运行找不到 Lite3.usd，9 秒后失败，没有产生交互。初始化子模块（固定提交 b452a1f，与旧工作区逐文件一致）后按任务书第 3 节重试 1 次，通过。这次失败计入运行次数。
3. 计划中的汇总脚本只读取 `<label>` 目录。现在增加 `resolve_run`，按 `<label>`、`<label>_retry1` 的顺序取第一个通过的运行，`summary.json` 的 `run_folders` 记录实际使用的目录。
4. `test_cfg_checks` 的转向指令测试原来用默认相对容差 1e-9 比较 float32 结果，改为 1e-6，实现代码未改。
5. `tests/source_scan/test_source_family_runtime_allowlist.py` 依赖从未提交的 `scripts/tools/runtime_progress.py`，在收集阶段就报错。本阶段测试时排除了它，与本次改动无关。
6. 子进程退出码不可靠：第 1 次运行失败时 `execution.json` 的 `exit_code` 仍为 0。判定以 `result.json` 的 `status` 为准，监督进程对失败运行返回非零。
7. E0n 和 E0p-L1 都在第 1731 个控制步结束，属于巧合：两次最长的回合都是上台阶完成。已核对 E0p 的初始偏移确实生效，两次运行没有逐环境相同的结果。
8. 完成判定沿用原定义，前进距离从地形块原点算起。初始 x 偏移最多 ±0.2 m，所以剩余距离相差不超过 0.2 m；配对比较使用相同起点，不受影响。

## 对 P1 的提示（建议，不改变规则）

三个目标条件在航向闭环下都是 0/8。P1 的确认标准要求固定码在 16 个新起点上比零码至少多完成 4 个。横坡上机器人走到 4.5 m 到 5.6 m 时，横向已偏移约 1.3 m，大约每前进 1 m 偏移 0.25 m；而安全过滤器的残差上限折合关节角只有约 1.7° 到 2.9°，固定码能否抵消这种侧滑还不确定。这是研究方案第 8 节列出的主要风险。如果 P1 测不出改进空间，会进入决策点 D-1。
