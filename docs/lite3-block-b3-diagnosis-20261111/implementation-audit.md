## 确认的奖励门控冲突

运行时 `stand_still.func` 指向安装包的 `isaaclab_tasks.manager_based.locomotion.velocity.mdp.rewards:stand_still_joint_deviation_l1`。它只检查 `norm(command[:, :2]) < 0.1`，不检查角速度。因此所有纯转向指令都会受到权重 -0.2 的站姿偏差惩罚。

项目本地 `mdp/rewards.py` 已有 `stand_still_without_cmd`，检查三维指令的范数，但当前任务并未使用它。不能因为本地有正确候选实现就认为训练实际使用了它。合成状态复现中，每个关节偏离默认 0.1 rad，总 L1 偏差 1.2；纯转向 ±0.5 rad/s 当前扣 0.24/秒，候选函数扣 0。零命令与仅 0.05 rad/s 的小命令仍保留该惩罚。复现执行的是实际源文件中的函数体，记录源文件 SHA256，结果见 `reward_reproducer.json`。

这个冲突早于 B2，不能单凭它解释所有新退化。`standstill-candidate.patch` 仅登记独立的 `SourceBlock-TurnGate-Deeprobotics-Lite3-v0` 任务，在 B2 基础上将这一项函数替换成本地现有实现；阈值、权重、采样、其余奖励与优化器配置均不改。补丁已做 `git apply --check`，本阶段没有应用补丁、启动候选任务或训练。下一阶段还需配置级检查和 GPU 冒烟验证。

## 其他奖励与采集核对

`feet_air_time` 实际调用 `feet_air_time_including_ang_z`，门控使用三维指令范数 >0.05，所以纯转向能激活足部腾空奖励。它不是只检查平移命令的另一个同类函数。偏航跟踪权重 1.5，指数核标准差 0.5；平移跟踪权重 4.0，标准差 0.25。动作一阶变化权重 -0.05；基础 gait_level 在 Flat 初始化时已设为 1.0。

Isaac Lab 步进顺序是物理更新、终止判断、奖励计算、自动重置、命令更新、观测更新。诊断仅包装奖励计算来读取已算出的分项和重置前状态，返回原结果；每步验证分项速率之和乘 0.02 等于环境奖励。不会为记录而再次调用有状态奖励函数。终止步的状态和接触用于失败证据，误差均值排除终止步和此后所有重置回合。运行时检查钩子内终止标记和环境返回标记一致。

记录的身体接触是传感器历史窗口中的最大力；它不等于某一项终止规则的连续计数。报告同时保存触发项，不能仅从有接触推断该接触导致终止。失败较多时，后期速度均值只代表存活回合；表格保留起始数、有效样本数、失败和截尾，不使用存活曲线掩盖失败。

受控两域共同摩擦与相对初始状态减少运行环境差异，但仍保留两域不同安全规则与场景几何；只能据此检验退化是否在两种场景重复出现，不能单独估计每一种摩擦或终止规则的因果作用。
