## 1. 目标、边界与成功定义

### 1.1 第一阶段要回答的问题

> 从同一个只在平地训练的 `model_1998.pt` 出发，在固定交互预算内，在线学习能否获得原策略不具备的低难度地形通过能力，并在关闭学习及返回平地后保留该能力？

“只有一个平地 PPO”约束的是初始技能来源。允许在平地采集数据、初始化训练用 Critic、增加零初始化适配参数；不允许导入复杂地形专家、地形适配器、目标地形 replay 或成功轨迹。Critic 是训练辅助网络，部署推理可以只有一个带适配参数的 Actor。

第一阶段不加载预训练恢复策略。仿真使用已有保护和物理复位流程。冻结平地 PPO、动作限幅和回滚都不构成对陌生地形的安全保证；真机试验另设部署验收。

### 1.2 分开报告三种能力

| 能力 | 定义 | 本计划位置 |
|---|---|---|
| 独立在线学习 | 每个学习 session 从相同平地技能、干净适配参数和空目标经验池开始，多回合获得一种能力 | 第一阶段主要结论 |
| 持续学习 | 学过 A 后继续学 B，再检查 A 和平地；各段预算累计 | 第二阶段 |
| 单回合快速适应 | 首次进入新条件后，不复位地更新参数并改善表现 | 第二阶段附加实验，单独报告 |

首次成功、参数改变、训练奖励上升和视频中偶尔通过，都不能单独等同于“学会”。经过多回合才成功，必须报告累计回合、控制步和墙钟时间。

### 1.3 工程目标与统计证据

下列数值是待验证的工程目标，正式试验前冻结，不是预期结果或无限调参的依据。

| 项目 | 第一阶段要求 |
|---|---|
| 主要终点 | 固定学习预算后，关闭更新，在新实例上的安全完成率及相对冻结 PPO 的配对差值 |
| 候选“学会”标准 | 独立学习器的平均完成率达到 80%，且比冻结 PPO 提高至少 20 个百分点 |
| 平地保持 | 相同速度、相同初态协议下无新增跌倒；速度误差增量不超过 `max(0.005 m/s, 5% × 基线误差)` |
| 可重复性 | 开发阶段 3 个独立学习器重复；正式阶段 5 个，每个模型评测 20 个新地形实例 |
| 统计结论 | 报告配对差值与 95% 区间。区间跨零时不宣称稳定优势；小样本限制明确保留 |
| 学习机制 | 梯度更新、候选版本通过验证、参数发布、控制端实际执行新版本，四项日志相互对应 |
| 实时性 | 单独测量完整控制循环的 p50/p95/p99、最大值及 20 ms deadline miss；不以纯推理耗时代替 |

没有达到 80% 但存在可重复提升，可报告“性能改善”；只有机制正确而没有收益，交付“在线更新可运行、尚未证明学会”。训练期间的所有跌倒、保护、复位和中止均计入报告。

安全完成定义为：沿预设路线到达终点并完成协议指定的末段稳定观察，过程中没有物理跌倒或达到终止阈值的身体碰撞/姿态异常。稳定段长度和各阈值在 T03 确定，所有方法一致。短暂限幅、保护介入和“已走到终点但随后跌倒”分别记录，不能只凭世界 x 超过终点判成功。

## 3. 算法方案与公平对照

### 3.1 主候选 A：低秩 Actor 在线 PPO

对原 Actor 的线性层增加 LoRA：

```text
W_i = W_i0 + (alpha_i / rank) B_i A_i
A_i 小随机初始化，B_i = 0；W_i0 与原 bias 冻结
```

第一版在四个线性层中加入 rank=2 适配，约 3698 个适配权重，另计探索参数；rank=1、4 只做开发筛选。零初始化要求是在真实观测上确定性输出与原 PPO 一致，不只在全零输入上检查。

保留原 45 维 Actor 观测，不引入新的全局输入归一化。Critic 首版使用可部署观测重新建立 `V(o)`，在平地新奖励数据上预热，再与 Actor 一起在线训练。若原 48 维 Critic 的输入和奖励均能正确复用，才评估保留/适配该 Critic 的分支；不能默认其数值与新目标兼容。

Actor 目标包含 PPO 更新和源技能保持：

```text
L_actor = L_PPO(current_on_policy_rollout)
        + lambda_flat * E_flat[||mean_pi(o) - mean_pi0(o)||^2]
```

平地项只作为行为保持约束，不能把旧平地 replay 当作当前策略的 PPO on-policy 样本。正式模型使用同一 Actor 推理，适配参数可合并到权重；保留不可变的 W0 文件作为来源与对照。

该方法借鉴 SLowRL 的低秩更新，但新 Critic、仿真复位和本项目保护流程与原论文不同，应称为本项目的低秩 PPO 候选，不能宣称完整复现 SLowRL。

### 3.2 主候选 B：共同接口下的残差 SAC

保留冻结 PPO，残差均值零初始化；目标地形 replay 为空。Critic 仅用经过协议核验的平地数据预热，之后使用平地和当前在线数据学习。

第一轮沿用已有双 Critic、Huber 损失、温度上限、请求动作语义和一步 target。已有实现允许 n=1/3/5，但 n-step 不与网络、奖励和动作范围同时变动；是否启用多步返回由独立开发消融决定。

初始温度 0.02、上限 0.05、Huber delta=1、平地比例由 0.75 过渡到 0.25 可作为现有开发起点，不能视为适合新接口的已验证值。零动作平地 replay 不提供非零动作的可靠 Q 覆盖，应检查外推误差；必要时补采小幅平地探索并登记成本。

### 3.3 观测协议必须分清

| 协议 | 两组共同可用信息 | 用途 |
|---|---|---|
| I0：第一阶段主比较 | 原 PPO 实际使用的同一份 45 维观测；不额外增加历史和足端接触 | 控制主要感知差异，比较 LoRA-PPO 与单帧 residual SAC |
| I1：第二阶段可选 | 相同的 49 维本体帧及 25 帧历史，接触来自相同来源 | 判断时间信息对陌生地形和持续学习的作用 |
| 历史工程参考 | 当前 49 维、25 帧 GRU residual SAC | 可报告整体系统效果，不与 I0 的差异归因成纯算法差异 |

I0 的 residual SAC 接口是待实现项。其 `frame` 直接取 PPO 观测，并设置单帧编码，不能直接从 49 维 raw frame 删四列来假定等价：两者顺序和缩放不同。适配器应显式保存 schema 和转换规则。

现有 I1 SAC 另从干净平地初始化做 3 个学习器、每个最多 20 回合的开发参考，以及冻结/平地复测，计入第 8 节的 600 条诊断总额度。I0 两组同时保留对应短预算检查点。不能直接用旧 v13 结果代替这个新参考，也不能仅因删去历史后 SAC 变差就宣称 LoRA 更适合工程部署。若 I1 参考明显更好，先补齐配对的历史条件方案，再冻结正式主比较；这一变更会顺延日程。

两种主候选的网络容量和动作参数化仍然不同，因此主结论是“相同信息和预算下的方法比较”。如需单独证明低秩约束的贡献，在开发集增加同观测、同 PPO 更新的全参数微调消融。

I1 若给 LoRA 增加历史条件分支，则另建方法版本，分支初始输出必须保持原 Actor 行为；编码器只能用平地数据初始化，或从随机初始化开始。两种选择分开登记，所有可训练参数和源数据成本计入报告。

## 4. 数据、奖励、动作和实时更新的共同约定

### 4.1 数据来源与信号权限

建立三个不同对象：不可变平地源数据、在线训练场景集、关闭学习的评测场景集。另区分开发协议与正式封存协议。

正式独立 session 的 Actor 只继承 W0；适配参数、优化器、目标地形 replay、学习率调度和随机状态从登记的干净初态开始。开发阶段学到的权重不能用于正式 session，目标地形上的 warmup 也必须计入在线交互预算。

Actor、Critic、奖励、更新触发器和回滚判据分别登记可用字段。I0/I1 主线不允许精确台阶边缘、地形类别或未来高度进入训练闭环；评测器可以使用几何真值判断是否过关。当前 rough shaping 有 `terrain_stage` 依赖，需要在共同主协议中移除或单列为 oracle 辅助实验。

仿真真实机身速度、足端力和世界坐标用于奖励时必须标为模拟传感/状态估计替代。它们不自动成为实机可用信号；实机阶段须替换并重新验证。I1 的接触信号也必须两种方法来源相同。

### 4.2 共同奖励

第一版只保留速度/偏航跟踪、实际前进、姿态、能耗、滑移/冲击、动作平滑以及物理失败项。可选抬脚项使用最近支撑面相对抬升，且两组一致；固定阶段名称不能决定何时奖励抬脚。

先输出各项奖励的均值、分位数与总占比，再冻结系数。目标是防止“原地抬脚”“不走但稳定”“靠随机动作过关”等策略。抬脚目标、步频和对角步序不在第一版同时加入。

奖励统一按控制步的实际时间定义：连续速率项乘 `dt`，事件项只在事件时计一次。基础 PPO 旧奖励和新在线奖励不能直接混用于一个 Critic；旧 replay 只有原始字段足够重算时才转换，缺失字段则补采。

### 4.3 请求动作与执行动作

两组在相同物理关节空间接受限幅、变化率限制和关节边界投影。统一记录：基础动作、请求动作、执行动作、归一化尺度、physical target、干预原因和动作版本。

开发起点可以采用当前未乘 gain 的物理修正上限 `[0.03, 0.05, 0.05] rad × 4`，但须经过平地动作探针与源策略幅度核对。所有额外 gain 都写进 manifest，并报告实际的乘积上限；不能把标称上限当实际探索权限。

若需要跨台阶的动作始终被裁剪，先做动作可达性诊断，再在开发协议下扩大范围；不能在看到正式失败后临时放宽。低秩适配不会消除同一保护层形成的动作上限。

PPO 的 old log-prob 对应采样时的请求动作和策略版本。SAC 的 Q 对应请求残差。投影是环境闭环的一部分，不能把投影后的执行动作重新标成策略原采样动作。由正常采样导致的物理失败及其负奖励应保留；非有限值、记录损坏或没有对应请求概率的外部接管样本按明确规则屏蔽，不能笼统删除所有失败样本。

### 4.4 回合内 PPO 的版本一致性

1. 控制端固定使用版本 v，采集完整的 256 步 buffer，同时保存 old log-prob、old value、末帧和终止类型。
2. 学习端在独立模型副本上更新。优化期间控制端继续用版本 v；这段过渡交互全部记入预算，但不拼入已开始更新的 buffer。
3. 通过有限值、行为漂移和动作检查后，发布 v+1。下一份 PPO buffer 从明确的新版本边界开始。
4. 旧版过渡样本可以用于诊断；第一版不把它们混入新版本 Actor 更新。丢弃/未用于梯度的样本数仍要报告。
5. 同一 buffer 可以包含多次物理回合，但 GAE 在边界切断。真实终止不 bootstrap；时间截断从 pre-reset 末帧 bootstrap，并切断跨 reset 的优势递推。

保存恢复须包含适配参数、Critic、优化器、探索状态、随机数状态、预算计数、策略版本和未完成 buffer 的处理方式。物理复位后清空历史、接触参考、上一步动作缓存和未完成跨界返回；学习权重和本 session 有效经验按协议保留。

### 4.5 控制与学习的资源隔离

当前 `play_online_adaptation.py` 的控制和梯度更新共享 `control_update_lock`，控制计时又在获得锁之后开始。新计划必须测量锁等待、设备同步、观测准备、推理、参数发布、模拟推进、录像与总循环耗时。

第一版优先使用 CPU 控制推理副本和独立学习进程，或在测量支持时使用独立设备；禁止梯度优化持有控制全局锁。参数双缓冲发布必须完整且可回滚。Isaac Lab 自身的模拟/录像开销单列：没有达到真实墙钟 50 Hz 时，可以报告仿真学习结果，但不能宣称已经满足真机实时控制。

## 5. 地形、种子和评测协议

### 5.1 第一类地形的选择

优先复用连续粗糙道路，在开发集测试 1、2、3 cm 起伏；如果基础 PPO 已几乎全部通过，则转向现有 2 cm 台阶或登记的新低摩擦条件。基线难度筛选希望找到通过率大致 20%–60%、且仍有有效行走数据的条件。这个范围是开发诊断，不是为了制造正式结果而事后挑场景。

若所有候选都太简单或完全不可行，输出难度诊断，调整开发任务后重新登记；保留旧结果。高度之外还需固定障碍宽度、间距、坡度、接触材质和道路长度。

| 阶段 | 地形范围 | 约束 |
|---|---|---|
| 源分布 | 原 PPO 平地训练分布及允许的平地初始化采集 | 不加入台阶/粗糙面的预训练 |
| 第一阶段 | 一类低难度地形，如 1–3 cm 连续起伏 | 正式学习与评测使用不同实例，任务分布预先登记 |
| 第二阶段独立学习 | 第二种机制不同的挑战，如低摩擦或 2 cm 台阶 | 重新从干净平地初态开始，不继承第一类经验 |
| 持续学习扩展 | A → 平地 → B → A → 平地 | 同一 session 保留经验，总预算相加 |
| 更难扩展 | 4 cm 台阶、较强起伏或曲面 | 前一阶段通过后才进入开发，不预先承诺学会 |

低摩擦必须核对历史随机化范围和材料 combine mode，记录实际组合摩擦，不能只根据新配置的一个数值宣称 OOD。曲面需要相对地表高度和路线进度，不能用固定世界 z/x 判定所有地形。

### 5.2 独立种子与封存

manifest 分别记录 `learner_seed`、`training_terrain_seed`、`evaluation_terrain_seed`、初态/扰动随机种子和评测重复编号。正式的 5 个学习器使用预先分配的训练场景实例；训练场景与 20 个冻结评测实例不重叠。每种方法使用相同配对安排，方法不能根据评测分数改参数。

同一平面上只改变一个没有影响实际状态的随机种子，不算独立重复。同一学习器的 100 个连续回合也不是 100 个独立学习器。评测的 5 × 20 个结果要按学习器与场景的层级统计。

v11/v12/v13 已使用的 benchmark 属于开发资料，不再称为全新封存测试。正式配置、种子清单和选择规则先固化，再运行；可以在正式训练场景执行预先规定的在线更新，评测场景则关闭更新且不入 replay。

### 5.3 预算和模型选择

开发顺序：单案例短探针 → 每配置最多 20 回合筛选 → 两个候选各 3 个学习器、最多 100 回合。每条物理轨迹最多 2000 个控制步，即最多 40 秒仿真时间。

正式每个独立 session 目标预算为 **200000 个新控制步**，单轨迹最多 2000 步，物理回合硬上限 200。先触及控制步、回合或登记的墙钟上限即停止。200000 步对应 66 分 40 秒仿真交互，不等于相同墙钟时间，也不是“20 分钟内学会”的承诺。若回合上限提前触发，按受预算/失败限制的结果报告，只在共同达到的控制步上比较学习曲线。

开发期冻结复测安排在约 20%、50%、100% 预算点，基线在零预算另测；与 I1 参考共用诊断额度。正式期间首先按预定预算保存 checkpoint，主要冻结复测和平地物理检查放在终点，以符合预算表。正式学习中的平地锚点来自已登记源数据；如增加中途物理复测，须预先列入额外预算并声明其结果是否影响算法。

固定在 0、25000、50000、100000、200000 步保存模型与学习状态。正式主要终点评估预算结束时控制端实际使用的模型；如果算法按预定机制回滚，评估回滚后的模型。开发最佳 checkpoint 可以作诊断，不能根据正式评测成绩挑模型。未达到预算的 session 使用实际最终模型，并保留中止原因。

冻结复测、平地检查、初始化采集和控制过渡样本分别记账。复测数据不用于训练；“只算成功片段”的交互预算无效。

### 5.4 记录哪些指标

| 层面 | 必须记录 |
|---|---|
| 任务 | 完成、剩余距离、单位预算内进度、速度/偏航误差、学习曲线面积 |
| 步态 | 每足支撑/摆动时长、步频、占空比、相对支撑面抬升、滑移、机身姿态 RMS、动作变化率 |
| 能耗 | 关节机械功率估计和有效前进段 CoT；低位移时不报告失真的 CoT |
| 风险 | 跌倒、非足端接触、保护触发、回滚、复位、峰值关节速度/力矩、终止原因 |
| 学习 | Actor/Critic 实际更新数、数据利用率、KL/行为漂移、熵、梯度、Q/TD 或 value error |
| 执行 | 采样版本、发布版本、每版执行步数、队列深度、锁等待、完整延迟、deadline miss |
| 成本 | 所有控制步、优化时间、初始化/检查交互、墙钟、视频/日志/checkpoint 大小 |

“相对上一支撑面的抬升”不是脚底对前方障碍的净空，报告时使用正确名称。瞬时四腿不对称也不自动是坏步态，需要结合支撑、前进和能耗评价。

## 8. 实验预算与资源安排

### 8.1 第一阶段预算草案

先固定预算的计算方法，W1 根据实测成本确认能否承担；如需缩减，在正式运行前缩范围，保留独立重复。每行的控制步是上限，实际停止和早终止另记。

| 项目 | 数量与上限 | 控制步上限 |
|---|---|---:|
| 平地基线 | 3 速度×5 初态×2000 | 30000 |
| 两候选首次闭环 | 2 方法×1 学习器×20 回合×2000 | 80000 |
| 短配置筛选 | 最多 6 配置×1 学习器×20 回合×2000 | 240000 |
| 长程开发 | 2 方法×3 学习器×100 回合×2000 | 1200000 |
| 匹配探索但不更新的开发对照 | 2 方法×3 随机重复×20 回合×2000 | 240000 |
| 开发复测、难度探针与有限消融 | 共最多 600 条×2000；超出前重新缩减后续范围 | 1200000 |
| 第一类正式在线学习 | 2 方法×5 学习器×200000 | 2000000 |
| 正式终点与平地检查 | 10 个学习结果×(20 目标实例+15 平地实例)×2000 | 700000 |
| 配对基础 PPO 检查 | 5 组配对初态×(20 目标实例+15 平地实例)×2000；可在两方法间复用 | 350000 |
| 合计 | 不含需要补采的源数据和第二阶段 | **6040000** |

源数据优先复用已有 100000 条；若无法重算新奖励/观测，最多另登记一份 100000 步的平地补采，单列来源与成本。初始化 Critic 的计算不计环境步，但计 GPU/CPU 时间。不能将旧 PPO 训练和旧平地采集描述成零成本。

6040000 步相当于 3020 条完整 2000 步轨迹。如果每条实际花 3 分钟，约 151 GPU 小时；6 分钟则约 302 GPU 小时，均再预留 30% 资源缓冲。它们只是换算示例，不是当前硬件速度测量。新 PPO 的过渡采样和 SAC 的回放优化成本须分别实测。

第二类独立学习的最低新增预算为赢家×5 学习器×200000=1000000 步，加冻结评测和配对平地检查最多 700000 步。持续学习和 T12 扩展另列预算，不把它们悄悄包含在“第一阶段 100 回合”中。

预算不足时，先去掉 T12、缩为一种挑战、减少开发候选；不通过删除失败、反复使用封存集或把同一 session 的回合当独立样本来节省重复。

### 8.2 录像、存储与并发

所有正式物理轨迹保存录像与原始遥测，包括失败。以每 2000 步视频 20 MB 为示例，第一阶段约 60.4 GB，实际以 W1 测量为准；此外还需 replay、checkpoint、日志和临时渲染空间。

逐步日志存单帧状态和 episode/version 索引，历史窗口可以重建，避免每步重复写整段历史。每个回合保存轻量参数与汇总；完整 replay/优化器快照保存在固定预算点、恢复点和最终状态。所有保留规则在长跑前登记，历史资产不自动删除。

允许在空闲 GPU 上同时运行相互独立的实验，但每个学习器只能从其单机器人交互获得目标经验；不能把多个并行目标环境的数据合并后仍称为单机器人在线学习。首轮性能测量使用独占资源，之后的共享运行记录资源竞争和实际延迟。

## 9. 验证、停止与路线选择

### 9.1 对实现有意义的检查

- LoRA：真实观测初始等价、冻结参数不变、适配参数有梯度、恢复与合并一致。
- PPO：手工可计算轨迹上的 GAE、终止/截断边界、old log-prob 与版本一致、过滤动作语义、旧数据不混入 Actor 更新。
- SAC：共同 I0 schema、请求残差/Q 一致、平地 replay 转换、不丢失物理失败 target。
- 编排：更新发布与控制使用对应、回滚后缓存/版本一致、物理 reset 清理时间状态、resume 不重置总预算。
- 评测：关闭更新、数据隔离、pre-reset 终止记录、相同场景和命令、未知地形标识不影响训练动作。

先运行受影响的定向测试，再在观测、replay、target 或恢复发生改变时运行完整 `tests/online_adaptation` 回归。CPU 检查通过后运行短仿真并保存视频；单元测试不能证明物理步态有效。

### 9.2 停止规则

非有限状态/参数、观测/动作协议错配、恢复状态不一致、关键日志丢失或资源预算耗尽时停止该 run 并保留失败产物。普通物理失败按预定复位规则继续，计入交互与失败预算。

开发阶段若连续几组结果显示 Actor 几乎不更新，先分析 buffer、门控、拒绝率与发布；更新充分却动作总被裁剪，分析动作可达性；训练地形提高但新实例退化，分析过拟合与数据覆盖；回平地退化，分析跨阶段漂移和保持约束。每次修订只改变一个主要因素，并新建实验版本。

正式试验发生代码缺陷时，记录影响范围并作废受影响结果，修复后重新冻结协议。不能只重跑失败 seed 或只保留早期有利 checkpoint。

### 9.3 路线选择表

| 观察结果 | 决策 |
|---|---|
| LoRA 达到收益与保持目标，SAC 未达标或成本更高 | 选择低秩在线策略学习为主线 |
| SAC 的完成率/样本效率更好且保持合格 | 保留 SAC 主线，LoRA 作为对照，算法名称不预先决定结果 |
| 两者接近，区间宽 | 报告无法区分；按计算、部署复杂度选择工程实现，增加重复需另登记 |
| I0 两者都差，但已有历史参考明显更好 | 优先做配对 I1，检验部分可观测性，不直接把问题归因于优化器 |
| 两者都有严重保持失败 | 暂停扩地形，处理全局平地锚点、行为漂移和回滚；增加 rank 不能自动解决遗忘 |
| 两者在合理动作范围内仍无法进步 | 缩小到有可学习信号的挑战，或明确记录该严格 flat-only 设定下的失败边界 |

候选增益是否可靠，以独立学习器和场景的配对结果决定。bootstrap 需按学习器簇并保留场景配对，必要时对场景作第二层重采样；每个控制步不能当独立样本。5 个学习器仍可能不够精确，应报告区间宽度。

## 11. 文献依据与适用边界

本次讨论已核验以下论文全文/项目页；2026 年新方法的论文结果不作为本项目的复现结果。

| 文献 | 可借鉴内容 | 本计划中的边界 |
|---|---|---|
| [SLowRL，2026-03](https://arxiv.org/abs/2603.17092) | 低秩 Actor/Critic 微调、适配参数零初态、训练期恢复 | 原实验涉及 Go2、Vicon 和预训练恢复策略；没有证明本项目的 flat-only 新地形要求，主候选只是借鉴 |
| [CARO，2026-08](https://arxiv.org/abs/2608.24217) | 平地训练、动力学残差观测、Lite3 50 Hz 固定策略适应 | 需要重新训练带观测器输入的策略，不能直接作为现有 PPO 在线获得新权重的证明；留作可选泛化对照 |
| [Bridging the Gap: Enabling SAC for Legged Locomotion，2026-05](https://arxiv.org/abs/2605.24975) | 动作初始化、timeout target、multi-step 返回 | 主要证据来自并行仿真；当前项目已具备部分对应机制，按需消融，不承诺真机快速学会 |
| [SimDist，RSS 2026](https://arxiv.org/abs/2603.15759) / [代码](https://github.com/CLeARoboticsLab/simdist) | 冻结表示/奖励/价值，只适配动力学以减少遗忘 | 使用较大规模多地形模拟数据、地形高度图和规划；不直接纳入唯一现成平地 PPO 的第一阶段 |
| [Learning Fault-Tolerant Locomotion with Adaptive Gait Timing，2026-08](https://arxiv.org/abs/2608.07328) | 显式学习步频、潜变量对齐 | 原方法假设训练和部署可用地形高度；只将步频作为后续独立机制候选 |
| [LoComposition，2026-06](https://arxiv.org/abs/2606.15896) | 任务、运行约束、能耗的清晰分工 | 原方案有外感知；可借鉴奖励设计，不把其地形能力当纯本体实现 |
| [RLPD，2023](https://arxiv.org/abs/2302.02948) | 源数据与在线数据结合 | 用于 SAC/价值学习设计；不允许把 replay 直接当 PPO 的当前策略样本 |

第一阶段的价值在于严谨验证“从唯一平地技能出发能否在线获得并保留新能力”。采用 LoRA、SAC 或其他名称本身不是研究结论；能力、代价、适用范围和失败边界才是交付内容。

## 12. 2026-09-15 文献调研增补

新增 [生成式策略与 VLA 在线适配调研](lite3-generative-policy-adaptation-review-2026-09-15.md)，核对了用户提供的 USR、FlowDAgger，以及 DSRL、PA-RL、StructRL、HAF、ReSkill、RFS、LP-DS 等近邻。LoRA-PPO 与 residual SAC 继续作为基线；开发筛选可增加 PA-RL 式动作改进和结构化探索候选，优先使用原有筛选/诊断额度。

潜变量加残差、低频动作基、隐藏层适配和渐进门控已有相关工作，不能仅凭组合认定创新。动作投影导致的价值混叠也已有 CAPG、Marginal Policy Gradients 和 SE-RL/SP-RL 等近邻；先检查实际执行和价值学习瓶颈，再比较现有处理方法。若有证据表明固定平地先验仍限制新能力，再研究扩展条件、方向和能力保持。完整 diffusion/flow 方案需要额外的平地先验模型与数据诊断；人工纠正则单列为人工辅助分支。正式方法、阈值与预算仍在开发结束后冻结。
