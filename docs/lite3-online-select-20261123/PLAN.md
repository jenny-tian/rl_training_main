# 加快学习 D：整个会话在参数库里持续选择（C1-b-D）

2026-11-23。做法在当天的阶段 C 汇报和随后的改进说明里提出，用户回复确认。本文件在训练之前提交。

## 1. 要回答的问题

阶段 C 的增益全部来自前 8 次尝试的一次选择，之后的窗口修正让 7 cm 上阶从 64 降到 35。D 检验两件事：

1. 去掉扰动更新，整个会话持续在库里的几组参数之间比较，36 次尝试时能否保持并超过阶段 C 的结果。
2. 在领先的参数附近生成几组候选一起比较，能否超过库里最好的一组。

## 2. 已经做完的离线检查（没有新的仿真）

**修正阶段的参数移动**（`REFINEMENT_DRIFT.json`，脚本 `reference_online_library_drift.py`，写在[阶段 C 结果](../lite3-online-library-20261122/RESULTS.md)第 7 节）：36 次尝试后 60 个会话的平均移动是 −0.10 到 +0.30，会话之间的标准差是 0.92 到 1.37。

**持续选择的模拟**（`OFFLINE.json`，脚本 `reference_online_select_attempts.py` 和 `reference_online_select_offline.py`）：把 C0 的评估轨迹重放成每次尝试的窗口得分（在 c3 训练轨迹上与训练时的记录核对，2909 个窗口全部一致），再从每组参数的 240 次尝试里有放回地抽取，模拟 20000 个会话。表里是当前领先的一组在 240 个评估回合里的成功数的平均。

## 3. 学习器

代码 `ea_lpl/c1b_d.py`，变体 `d1` 和 `d2`。参数库、新地形、起点槽位、安全过滤都与阶段 C 相同。

- 每次尝试用一组候选参数，整个回合不变，不加扰动，没有梯度更新。
- 前 2 个回合每个并行环境用库里的一组并轮换，与 c3 的选择阶段相同。
- 第 3 个回合起，每次尝试按各组的成功次数抽样：每组从 Beta(1 + 成功次数, 1 + 未成功次数) 抽一个数，用最大的一组。
- 一次尝试的得分是成功记 1，加 0.01 倍的该次尝试窗口平均反馈（只在成功次数相同时分出先后）。平均得分最高的一组是当前参数，每个回合结束后更新，快照和评估用它。
- `d2` 在第 4 个回合结束后加入 3 组候选：领先和第二的两组在 tanh 空间里的中点；领先一组的两个摆动幅度乘 1.2；乘 0.8。候选与库里的参数用同样的规则比较。

与汇报里说法的两处不同，都来自上面的离线检查：比较用是否成功，没有用窗口反馈；尝试的分配用按成功次数抽样，没有用固定的 2 次加 2 次。

- 对照直接用阶段 C 已有的结果：C1（`c3`）、C2（`w2`）、C0。评估起点相同，Frozen 组应逐回合相同。

## 5. 判定（训练前登记）

- **主判定**（两个目标分别判定，针对 D1，10000 步）：
  1. 对 Frozen 的成功率增益不低于 10 个百分点，且 95% 区间下限大于 0。
  2. 对 C1 同一快照的配对差，95% 区间下限大于 0。
- **候选是否有用**：D2 对 D1 在 10000 步的配对差，95% 区间下限大于 0。
- 其余三项沿用，在 10000 步判定：姿态终止增加不超过 2 个百分点，各地形族成功率下降不超过 5 个百分点，平地速度误差比不超过 1.10。
- 只作描述：各快照 D1、D2 对 Frozen、C1、C2 和 C0 最好一组的配对差；D0 各候选的成功数；每个快照各会话领先的是哪一组；实际结果与第 2 节模拟值的差。
- 区间用按会话重采样的自助法，10000 次，种子 0。

## 6. 训练前检查

1. 单元测试：前两回合的轮换、得分和领先的一组、按成功次数抽样、不加扰动、候选的生成和上限、不更新的组不改参数、快照能被评估读入。
2. 两个新地形各做一次冒烟运行。

## 7. 没有把握的地方

- 第 2 节的做法是在同一批评估数据上比较了 12 种规则后选的，模拟值可能偏高。
- 模拟用的是评估起点上的尝试，训练时每个会话只有 4 个起点。
- 按是否成功来比较，在 7 cm 上阶上会更多地选中 6 cm 箱体那一组（成功 81，姿态终止 50）。模拟的姿态终止是 28，低于原步态的 39。
- 候选只在领先参数附近取了 3 组，范围很小；摆动幅度乘 1.2 后多数已到上限。
