# 原部署入口离线核验结果

用户已批准最多两段启动检查加十二个正式路线回合。本阶段在前置离线核验中发现真实接口问题，按批准的停止条件结束：启动检查 0 段、正式回合 0 个、物理步数 0、优化更新 0。没有连接机器人或启动 UDP 控制器，部署项目保持只读。

## 已通过的内容

zero10100 和 B 均从 SHA256 锁定的检查点导出为独立 ONNX 文件，保存在本地 logs。使用前阶段保存状态每模型均匀选取 1024 个观测，与原 PyTorch actor 对比，最大动作绝对差均为 7.153e-7。输入为 45 维，输出为 12 维，模型结构和权重无需修改。

实际编译部署项目使用的 `lite3_test_policy_runner_onnx.cpp`。隔离副本只把固定模型路径改为测试路径，添加两个只读观测访问器；没有改控制或动作逻辑，完整差异见 [instrumentation.patch](instrumentation.patch)。调用的是 C++ ONNXRuntime 1.22.0，Python 对照使用 1.27.0。

归一化命令 `(0.5, 0.125, -0.625)` 实际进入策略为 `(0.4, 0.1, -0.5)`，0.8 缩放正确；连续运行的上一动作、关节顺序、默认角度和动作尺度映射也通过。相同实际观测下，C++ 与 Python ONNX 输出最大差小于 5e-9。

## 阻止后续回合的问题

### 1. 上一动作向量没有初始化和重置

原 `.h` 声明了动态向量 `last_action`，构造函数与 `OnEnter()` 都没有将其设置为 12 维零向量。第一次调用动作入口时，其长度为 0，却参与构造 45 维观测。

- 保留 Eigen 断言的构建：两个模型均在第一次动作调用触发 `Too few coefficients passed to comma initializer`，进程返回 -6。只在离线探针中复现，已禁用 core 文件。
- 原 Release 语义构建（关闭断言）：本次探针成功运行，观测末 12 项因 `current_obs_.setZero(45)` 恰好保持为零。不能据断言失败声称用户的 Release 二进制一定不能走路。
- 重新进入策略：`OnEnter()` 不清理已有 `last_action`，会沿用上一轮动作。两个模型均复现。与重置为零的同状态参考相比，最大关节目标差分别约 0.1451、0.1469 rad，即约 8.31°、8.42°。这是合成固定状态下的接口差异，不是实机跳动或跌倒测量。

建议后续仅在隔离副本中给 `last_action` 分配 12 维，并在每次进入策略时清零，再复核首次与重新进入的语义。该修正本轮未执行。

### 2. UDP 接收少复制最后一个力矩字段

Python 状态消息为 `double` 时间戳加 45 个 `float`，总长 188 字节；C++ 缓冲区有 47 个 float 的空间，但只复制 `46*sizeof(float)`，即 184 字节。

使用同格式合成报文，最后一项关节力矩发送值 45，解析结果为 0，倒数第二项仍正确。当前 actor 不使用关节力矩，这个错误不能直接解释上阶表现；它会使状态记录不完整。完整部署验证应修正长度检查及复制字节数。

### 3. 另外两项差异需区分证据强度

- C++ 对关节速度直接乘 0.05；训练及独立评估先将原始值裁剪到 ±100 再缩放。合成 dq=150 rad/s 时，C++ 输入为 7.5，训练口径为 5。这是边界语义差异，不代表当前已观测到 150 rad/s。动作也未显式按训练的 ±100 裁剪，本阶段未将其解释为已发生的正常步态故障。
- 策略线程以主线程看到的时间戳变化次数进行 12 次抽样，而不是按流逝的仿真毫秒直接触发；接收、状态刷新与动作线程之间也有共享数据。静态检查不能证明实际运行丢帧或发生竞争，本阶段没有测量实际控制间隔。

独立 MuJoCo 的 12 ms / 30 Nm 结果仍然有效；它不等于完整 C++ 部署入口已经通过。此次导出和映射等价检查通过，因此没有证据要求重新训练基础模型。
