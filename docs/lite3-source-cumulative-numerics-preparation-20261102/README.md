## 累计预算与初始化

上阶段真实联调为 run1 消耗的 384 条交互继续计入各硬上限。数值试训从原始登记
actor 均值、std=1 和全新 critic/optimizer 开始，不载入诊断后的权重，不自动恢复。
放弃诊断权重不会退还预算。三节点表示同一次训练轨迹的累计位置，不能分别重新
开始并叠加消费；当前实现只允许 numerics，midpoint/pilot 续训仍明确拒绝。

每次完整更新为 120 环境 ×24 步，即 2,880 条交互，不能向上凑足硬上限。

| run1 节点 | 硬上限 | 已计费 | 计划正式更新总数 | 计划正式交互 | 连同诊断的累计计费 | 未使用额度 |
|---|---:|---:|---:|---:|---:|---:|
| numerics | 262144 | 384 | 90 | 259200 | 259584 | 2560 |
| midpoint | 1048576 | 384 | 363 | 1045440 | 1045824 | 2752 |
| pilot | 2097152 | 384 | 728 | 2096640 | 2097024 | 128 |

run2/run3 当前未消费，对应节点为 91/364/728 次更新。本阶段不预留任何生产预算。
数值试训若将来获准，由父进程一次预留整笔 259,200 条，失败或部分运行也保留整笔
计费。台账用文件锁和原子写入，拒绝过期快照、重复启动及失败诊断历史；已结算结果
不可重写。旧 v1 从零开始的清单仍拒绝 run1 已有的 384 条消费。

监督器固定 GPU0、启动 120 秒、总运行 900 秒、清理宽限 15 秒；启动前要求至少
12,288 MiB 可用显存，保留卡级采样和独立进程组。子进程复核提交、远端 SHA、源码、
原始 checkpoint、台账预留和批准清单。退出 0 还须报告、计数、有限 loss、完整更新
收据、actor/critic 变化、最终 actor 架构/哈希和关闭证据一致。父进程负责结算。
进程被外部强杀等无法结算时，`reserved` 仍占预算，不能凭缺失报告重新启动。

监督器的 CPU 故障测试使用临时台账和普通 Python 子进程；其中的 GPU 查询返回值、
运行资格和指标记录均为测试构造数据，不能用作真实运行证据。

## 选定规模检查提案

详细参数见 [selected_scale.proposal.json](raw/proposals/selected_scale.proposal.json)。
16、32、60、120 环境依次检查，每次均另行批准，禁止自动扩容或重试。G1 每规模一
个零动作步；120 环境 G2 计划 24 控制步、选择性 reset 和一个完整平衡票据块。
G3 计划 2,000 控制步/8,000 物理子步、保留六家族全部条件、Flat 全进度和稳定保持
证据。普通任务结束记录后 reset；接触、扫描、状态或归属完整性错误立即停止。
旧策略不必先通过所有地形任务。以上当前均未执行。

120 环境有 2,040 个机器人刚体和 2,064 个过滤目标，形成 4,210,560 个 pair。
仅每帧的 float32 力、uint32 count 和 net force 就需 67,393,440 bytes；8,000 帧
为 539,147,520,000 bytes，尚未计详细接触点、JSON、扫描和运动记录。

因此提案保留全部 count 非零或 force 非零的 pair，其他项按零重建；每帧仍检查
全矩阵有限性、跨环境接触、容量、力重建、net/pair 一致和归属，记录原始接触点及
故障快照，再独立 CPU 重建核对。不能只记录 count 非零的 pair 而丢失 force-only
项。容量 1,048,576、原始日志上限 2 GiB 均为候选，须用实际占用验证。
**120 环境稀疏采集执行器尚未实现，本阶段只完成方案和空间计算。**

G4 分开登记两种吞吐：

- collection：48 步预热、240 步测量，保持生产安全和有限性检查，关闭逐子步重日志；
  候选门槛 600 transitions/s、reset p95 不超过 1 秒，PPO 更新为 0。
- end-to-end：场景完成后，实测采集、PPO 和生产持久化合计吞吐，门槛候选为 600
  transitions/s；它只能在真实数值试训后判定。600 是略高于 2,097,152/3,600 的
  一小时稳态 Pilot 目标，不是八环境重日志探针的实测性能。启动时间单列。

这些阈值仍是待批准提案。G1/G2/G3 和 G4 collection 通过后可申请限定数值试训；
启动时 `g4_end_to_end` 保持 pending，不提前声称完整 G4 通过。即使数值试训成功，
也不自动授予完整 Pilot、技能或正式选模资格。

## 六家族全部 15 条件的 Source-only 选模提案

详细协议见 [source_selection.proposal.json](raw/proposals/source_selection.proposal.json)。
每个训练 seed、每个条件各自判定，不合并不同训练 seed 的结果，不用训练 reward
选模，不读取 Development/Sealed 反馈。

每个节点有 15×5=75 回合；各条件至少 4/5 同时完成 9m、50 个稳定步及质量要求，
任何回合紧急停止、无效状态或非足端接触终止计数非零均拒绝该节点。条件包括 Flat、
多尺度粗糙、四向坡、上下台阶、四向坡加粗糙和三种摩擦布局。失败和负前进量保留。

| 通用质量指标 | 候选上限 |
|---|---:|
| 平均/RMS 速度误差 | 0.20 / 0.25 m/s |
| roll / pitch 峰值 | 各 0.40 rad |
| 横漂峰值 | 0.30 m |
| 接触滑移占比 / 安全投影占比 | 各 10% |

通用上限是把已有 Flat/台阶草案推广到全条件的提议，未完成指标校准，尚未锁定。
Flat 另用相同几何/状态编号的原始冻结 actor 基线约束退化：roll/pitch 平均差不超过
0.10 rad，其他指标不超过 0.05 对应单位；基线本身不必通过任务成功门。

台阶要求三级完成、卡滞零，出现前足碰撞的回合最多 1/5，20 N 上升沿检测器必须
另做运行资格验证。坡面要求 5 度方向和出口过渡证据；粗糙要求真实网格峰谷差和至少
两种空间尺度审计；摩擦要求布局、材料绑定及各区域滑移记录。实际指标采集器尚未
实现/取得资格；离线校验器只接受明确归一化的 `lite3_source_episode_metrics_v1`。

选择序列：最大化最差条件合格回合数，继而最大化各条件等权合格数总和，再最小化
等权 RMS 速度误差，最后优先较早更新。仅当 numerics 和 midpoint 两节点都通过
全部 15 条件时允许 midpoint 提前结束，否则完成三节点候选序列。随后只确认已选
的一个 checkpoint，确认失败不能重新选模。当前提供离线决策函数和协议，未实现
真实评估调度或跨进程的一次确认执行登记。

原预留首三条件和全部选择/确认 seed 区间保持。state ID 仍是确定性 reset 的记录
编号，不代表随机状态。几何身份须由实际局部网格、材料和参数规范化 SHA 确认；
同一几何重复 5 次只报告重复试验，不生成独立几何样本的成功率置信区间。评估总量
上限为三 seed 选择 675、确认 225、共享冻结 Flat 基线 10，共 910 回合；只读评估
单独报告，不混入 PPO 学习预算。
