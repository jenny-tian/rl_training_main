## 发现的位置／速度参考点问题

[当前依赖与 USD 的静态审计](reference_point_audit.json) 显示，环境安装所指向的 `ArticulationData` 中：

- `body_pos_w` 对应 **link 坐标系原点位置**，这是当前碰撞包络所围绕的点。
- `body_lin_vel_w` 对应 **质心线速度**。
- 同一点预测需要 link 原点的速度；该依赖已有显式 `body_link_lin_vel_w`，其计算关系为 `v_link = v_com − ω × (R·r_com_in_link)`。

模型中 `FL_THIGH` 的质心偏移为约 `[-0.0039245,-0.014632,-0.025146] m`，因此转动时两种线速度一般不同。现有 wrapper 把 link 位置与质心速度组合用于外推。**本次已完整确认这一实现的实际触发，尚未验证参考点统一后的预测结果。** 日志未记录全部刚体角速度和姿态，无法事后精确算出末步左前大腿应使用的 link 速度，因此不能认定这是误报或证明实际已越过地形边缘。

`ArticulationData` 与 editable-package finder 的哈希是在本次运行后首次记录，原 232 项冻结清单没有包含它们；本归档不追写原 manifest。后续离线修正应将它们纳入输入冻结并增加真实 COM/速度定义回读。

## 为什么仍有约 0.35 mm 的重建残差

这里的残差定义为“记录的位置变化”减去“离散速度积分”。对本次与上次相同的样本：

\[
r=(y_N-y_1)-\sum_{i=1}^{N-1}\frac{v_{y,i}+v_{y,i+1}}{2}\,\Delta t,\quad\Delta t=0.02\ \mathrm{s}.
\]

它不必精确等于零。日志只有每个控制步末的速度，而仿真每 0.005 s 更新一次；梯形积分无法还原控制步内部所有速度变化、积分及约束求解中的位置更新。浮点状态精度也可能产生差异。现有日志不能逐项量化这些来源。

[独立残差核算](residual_explanation.json) 给出了更具体的证据：

| 核算量 | 数值 |
| --- | ---: |
| 记录的净横移 | 1.5069433472 m |
| 由机体速度和四元数重建的积分 | 1.5065935093 m |
| 直接使用记录的世界速度做梯形积分 | 1.5065935206 m |
| 两种积分的差值 | **0.00001131 mm** |
| 直接世界速度积分后的残差 | **0.349827 mm** |
| 原报告残差占净横移 | **0.023215%** |

因此，**坐标旋转舍入误差不是这 0.35 mm 的主要来源**。改用左／右矩形积分会分别得到约 +2.328 mm／−1.628 mm 的残差，也表明数值积分方法会影响重建结果；这并不是对梯形误差真值的测量。

位移和积分都从第一条 0.02 s 样本开始，所以“没有记录 reset 至第一条样本”不能解释这里的残差。模型中躯干 `TORSO` 的质心偏移为零，Source 配置也关闭了 COM 随机化；左前大腿的非零质心偏移不能直接解释躯干残差。实际运行 COM 未回读，不能声称完成了全部参考点／误差归因。若要进一步分解，须在未来获批的运行中记录同一参考点、相同时刻的逐物理子步位置和速度。

0.35 mm 说明现有运动学重建与记录轨迹接近，但不能据此断定策略、接触或初始化中哪一项导致了明显横漂。
