# 最终模型在原始 Isaac Lab 环境中的上台阶诊断

本阶段完成 480 个正式回合。最终 10000 次更新模型在原始 Isaac Lab 环境中仍无法可靠上台阶，说明问题在原训练环境的固定指令测试中就存在。MuJoCo 迁移差异可能继续影响表现，但无法单独解释这次失败。

本阶段冻结模型，只评估和记录，不进行 PPO 更新，不调整训练奖励，不加载参考部署模型，不连接实机。模型 SHA256 为 `5cf4c1160b6f5b7b5102844526b26f3886c27562d98ea9558e3fa09da504f5a1`，与训练最终检查点一致。

## 测试条件与可信范围

- 复用训练时的参考环境、45 维 actor 输入、393 维 critic 输入、动作顺序和缩放、奖励函数、终止条件、USD 机器人及 PhysX 设置。20 个共同加载的训练源文件 SHA256 与训练结束记录一致。
- 控制周期 20 ms，物理步长 5 ms；髋关节/膝关节扭矩上限为 24/36 Nm，保留原 DelayedPDActuator 和 0～1 个物理步长的延迟分布。
- 使用训练原生方形台阶生成器，固定台阶高度为 5、10、15 厘米，踏面 30 厘米，外加平地对照。生成器有效块尺寸 8×8 米。射线检查确认，从中心向外有七次升高，第一立面约在 x=1.20 米，末级约在 x=3.00 米。
- 速度为 0.32、0.4、0.6 米/秒，每个组合 20 个起点；4 种地形×3 档速度×20 个起点×2 组物理条件，共 480 回合。0.32 米/秒用于覆盖上一轮未测试的较低速度。
- 机器人初始 x=0.25±0.05 米，y=±0.10 米，偏航±0.03 弧度，初始速度为零；先以默认关节位置站立 1 秒，之后零指令 0.5 秒、0.5 秒线性加速，最长 20 秒。
- `nominal`：关闭观测噪声和质量、惯量、质心、增益随机化；机器人摩擦固定为 0.9，恢复系数为零，仍保留原电机延迟分布。
- `training_randomized`：保留训练原有观测噪声、质量、惯量、质心、摩擦、恢复系数、增益和电机延迟随机化。起点、地形和指令仍是上述受控条件，并非训练全部分布的重放。
- 两组都采用部署时的确定性 actor 均值，不采样训练时的高斯动作噪声。因此结论针对可部署的确定性策略，不能推断训练采样策略从未偶然越过台阶。
- 地形升级关闭；奖励的全局 `gait_level` 固定为最终训练平均等级对应的值，约 0.976，避免仅放一行地形使奖励系数变成零。没有修改奖励公式和权重。

所有轨迹在自动重置之前记录，只统计首次回合。四脚越过某级要求足端全部超过立面并达到踏面高度、身体高度和倾角满足条件持续 0.1 秒。整段通过还要求四脚越过末级、机身越过安全余量、几何条件保持 0.25 秒，完成时有足端支撑且躯干未接触地形。侧向偏离超过 1 米单列，超时最后 5 秒前进不足 0.15 米记为卡住。

本轮台阶是原训练的方形环状七级，上一轮是 MuJoCo 直线六级；侧向边界及最长时间也不同，两轮整段通过率不能直接相减。本轮重点是能否越过第一级及接触后的行为。

平地对照在名义参数下通过 51/60，另有 8 次侧向越界、1 次超时；训练随机化下通过 47/60，另有 9 次侧向越界、2 次姿态异常、2 次超时。说明模型能持续向前走，但原环境中的方向保持与随机化稳定性也未完全达标。不能把平地对照描述成全部通过。

在 0.32、0.4、0.6 米/秒下，10 厘米台阶均没有越过第一级的样本。因此速度过快不足以解释该模型目前的上台阶失败。

## 已经确认的失败行为

10 厘米、0.4 米/秒、名义参数下 20/20 次卡住。卡住样本最后 5 秒的平均前进速度约 0.0001 米/秒，平均前进量约 0.0002 米。前脚中心高度的回合内 95 分位再按回合平均约为 0.0225 米，前脚水平接触力的对应统计约为 32.4 N。

训练随机化下同组有 18 次卡住、2 次姿态异常；18 个卡住样本的平均前进速度约 -0.0016 米/秒，前脚高度统计约 0.0249 米。碰到立面后缺少继续抬腿的反应，在两组条件下都出现。

名义参数固定起点 0 的例子中，最后 5 秒动作各关节标准差小于 0.00005，前脚中心最高约 0.02222 米。这是稳定停滞状态，不能只凭低姿态异常率视为安全完成任务。足端传感器记录的是合力，水平分量与足端位置结合支持抵住立面的判断；它不提供每个接触点的独立立面法向力。

## 实际奖励记录及代码问题

下面是名义参数、10 厘米、0.4 米/秒、20 个卡住样本最后 5 秒的平均加权奖励率。原环境每步奖励还会乘 0.02 秒，表中数值不是每步最终奖励。

| 奖励项 | 平均奖励率 |
|---|---:|
| 平面速度跟踪 | +2.905 |
| 转向速度跟踪 | +1.499 |
| 固定足端轨迹 | +1.125 |
| 对角步态项 | +0.292 |
| 机身高度 | -2.760 |
| 保持水平姿态 | -0.013 |
| 足端腾空时间 | 0.000 |
| 所有项合计 | **+2.018** |

训练随机化同组卡住样本的总奖励率约 +2.326。正奖励本身并不能证明停住优于爬阶，但这些记录确认：没有前进、没有抬腿，也能持续获得多项奖励。

具体值得修正或做对照验证的地方：

1. 速度跟踪核较宽。指令为 0.4、实际速度为零时，`4*exp(-0.4²/0.5)` 仍约为 2.905，相当于该项满分的 72.6%。当前没有直接区分成功越过台阶与长期抵住立面的任务奖励。
2. 足端轨迹项允许静态姿势获得相当部分分数。实际设置为零前后摆幅、5 厘米抬脚尺度、零支撑相长度参数、零速度误差权重；函数内部把支撑相长度截到 1e-6，轨迹几乎全是摆动相。实际卡住时这一项仍约 +1.125。它是软奖励，不是足端高度上限。
3. 腾空时间项只在首次落地时结算 `(腾空时间-0.5秒)`。没有离地再落地时得零；较短的步伐可能得负值。在固定起点的平地步行样本中，这一项最后 5 秒约 -0.556，卡住后则为零。这种取舍值得对照验证，不能直接认为该项一定鼓励更多抬腿。
4. 身体高度目标为 0.55 米，卡住时相对下方扫描地面的实际高度约 0.312 米，造成持续较大惩罚。保持水平姿态和垂直运动约束也可能影响爬阶探索；目前没有成功爬阶轨迹供同条件奖励比较，因此不能宣布它们是已证实的唯一根因。
5. 足端轨迹基准从首次调用时的第 0 个环境姿势缓存，并共享给全部环境。训练检查点没有保存这份奖励内部缓存，本轮重新按同一函数初始化并保存于 `initial.npz`。所以本轮奖励值是对原奖励函数的诊断计算，不能冒充训练当时的历史逐项奖励。该缓存只用于奖励，冻结策略的动作不读取它。

执行策略本身仍为无地形高度输入的 45 维网络，只有 critic 读取高度；没有增添高度输入或额外控制器。本轮不能证明无高度输入必然无法爬阶，也没有检验改变网络结构的效果。
