# 下一阶段建议：冻结模型，定位剩余转向与走偏问题

本文件为待批准方案。尚未执行下述补录，不增加训练、不修改奖励、不部署。需要用户确认后开始。

## 为什么先做这一步

动作保持系数从 0.5 改为 0 后，名义 5 厘米完整上阶从 9/60 提高到 49/60，说明本次设置中的上阶学习受到了该约束的明显限制。但是高速左转相对父模型仍退化，名义 3/5 厘米下阶各出现一次横向越界，随机化起步还出现一个父模型原本成功的新失败。

两端系数都没有恢复父模型的高速左转，现有结果不能保证把系数改成 0.1 就能解决。当前转向轨迹只记录机身、动作及合计奖励，缺少逐足接触时序和实际关节响应；仅凭这些数据还不能确定该修改哪一项奖励或动作约束。下一阶段补齐机制证据，再提交具体单项修正。

## 固定执行范围

1. 保持父模型 10000、本次零保持 10100 的检查点不变。上一轮组合 10100 继续复用已有机身与动作轨迹。
2. GPU 1 顺序执行父模型与本次模型的两种物理条件转向补录，共 4 次仿真，每次原协议 320 回合、1000 个控制步，共 1280 回合。保持原初始数组、16 类命令、每类 20 个起点、前 2 秒零命令、确定性均值动作和第一回合规则。
3. 使用独立观测入口，历史训练及评估源码不变。补录各腿足端位置/速度、接触力、接触与腾空计时、关节位置/速度/力矩、步态相位和参考足端轨迹。只读取原有状态，避免额外调用带状态的奖励函数改变运行。
4. 核验原有轨迹字段、初始数组、命令、终止结果和检查点哈希。若补录不能重现原协议，先定位差异，不把改变后的轨迹直接用于结论。
5. 下阶走偏使用本阶段已保存的轨迹，不再另跑下阶仿真。比较完整通过和横向越界回合的航向、横向速度、足端支撑与首次偏离时点。
6. 优先检查高速左/右转的抬脚、支撑、滑移及关节响应差异；从记录值离线重算纯转向奖励修正，分别说明原参考计分与实际训练公式的差别；检查随机化新失败起点 57 在前 0.82 秒的姿态和接触演变。
